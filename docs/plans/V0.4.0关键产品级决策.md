# V0.4.0 关键产品级决策

> 文档状态：决策稿（2026-09-10）
> 适用范围：V0.4.0 手机远程的公网接入方式、鉴权安全模型与登录页文案
> 关联文档：`V0.3.3-V0.4.0-Plan.md` §7（手机远程架构与分期）、`docs/手机远程语音说明.md`（用户侧指引）、`V0.3.7-契约冻结.md`（远程协议契约）
> 本文只冻结决策与验收标准；执行级任务分解在 V0.4.0 执行计划中展开。

## 0. 决策一览

| 编号 | 决策 | 取代的旧做法 |
| --- | --- | --- |
| D1 | 公网接入改用 Cloudflare Tunnel，Tailscale 退出推荐路径 | `tailscale serve --bg 8765` 提供 HTTPS |
| D2 | `--serve` 默认只绑回环，局域网直连改为显式开启 | `WSServerMode._host` 固定 `0.0.0.0` |
| D3 | 配对码增加失败限流与指数退避 | `claim()` 无尝试计数 |
| D4 | 同时只有一枚配对码有效，生成新码即作废旧码 | `issue_code()` 只清理已过期条目 |
| D5 | 设备令牌增加绝对有效期与空闲有效期 | 令牌签发后永久有效，仅手动撤销 |
| D6 | 控制面方法只应答回环来源 | 任意已鉴权连接均可铸造配对码、撤销设备 |
| D7 | 隧道 URL 视为公开信息，不作为访问控制 | 隐式依赖「地址只有自己知道」 |
| D8 | 登录页标语改为「一条会话，两条工作轨。」 | 「一间房，两盏灯。」 |

D1—D7 构成一组：公网入口从「自建虚拟网络」换成「公网隧道」之后，网络边界不再提供任何保护，鉴权层必须独立撑起全部防线。只做 D1 不做 D2—D7，是把当前的局域网信任模型原样搬到公网上。

---

## 1. 现状

当前实现（V0.3.9 候选基线）如下。

**入口。** Tauri 桌面端启动 Sidecar 时固定带 `--serve 8765`（`desktop/src-tauri/src/lib.rs:256` 的 `REMOTE_SERVE_PORT`，启动参数在同文件 453 行与 463 行）。`WSServerMode` 在 `0.0.0.0:8765` 上跑单个 aiohttp 应用，同时承载 `GET /ws` 升级与 PWA 静态资源（`src/pair_harness/desktop_backend/ws_server.py:140`、`pwa_static.py`）。

**鉴权。** `PairingService`（`pairing.py`）生成 6 位数字配对码，TTL 300 秒，一次性；`claim()` 兑换为 `secrets.token_urlsafe(32)` 令牌。每个请求经 `WSServerMode._handle_frame` 调用 `authorize()`，除 `UNAUTHENTICATED_METHODS`（目前只有 `remote.pair`）外都要求有效令牌。令牌绑定到连接，鉴权后不允许中途换令牌。撤销会立即断开持该令牌的已建立连接（`close_connections_for_token`，关闭码 4401）。

**持久化。** 配对状态经 `export_state()` / `load_state()` 存进 SQLite 的 `remote.pairing_state`（`application_service.py:3641`、`3656`），包含令牌原文、设备名、签发与最近使用时间、撤销集合、审计条目。

**HTTPS。** 由用户自行用 `tailscale serve` 提供，应用不内置证书方案，局域网 http 下手机语音入口如实禁用。

**审计。** `connect`、`auth_failed`、`command` 三类条目，不含消息正文与密钥（`pairing.py:100`）。

## 2. 现有安全缺口

以下是当前实现里可复现的问题，不是理论风险。

**G1 监听面常开。** `0.0.0.0` 绑定让任何局域网设备都能打到 `/ws`。命令面只靠令牌拦，而 `/ws` 上存在一个免鉴权方法 `remote.pair`。

**G2 配对码可枚举。** 6 位码空间是 10⁶，`claim()` 没有失败计数、没有退避、没有来源封锁。局域网内一台机器可以持续提交候选码直到命中。码的 TTL 是 300 秒，但攻击者不需要在同一枚码上打满整个空间——他可以一直打，等用户下一次生成。

**G3 多码并存。** `issue_code()` 只调用 `_evict_expired_codes()`，不清理未过期的旧码。用户每点一次「重新生成配对码」，就多一枚同时有效的码。这直接放大 G2。

**G4 令牌永不过期。** `_TokenEntry` 只有 `issued_at` 与 `last_used_at`，没有到期字段。令牌一经签发，在用户手动撤销之前一直可用。手机丢失、备份被翻出、截图里的令牌，都属于这一档。

**G5 权限无分级。** `authorize()` 的结论只有「有合法令牌」和「没有」。已配对的手机因此可以调用 `remote.issue_code` 铸造新配对码，也可以调用 `remote.revoke` 撤销其他设备。`_remote_issue_code` 的 docstring 明确写着「仅桌面 stdin 路径与已鉴权远程连接可调用」。一台被配对的设备能自行扩散访问权，撤销者与被撤销者不分主次。

**G6 来源不可区分。** `authorize()` 看不到请求来自回环、局域网还是隧道。控制面与业务面在同一张方法表上，没有按来源收窄的余地。

把入口换成公网隧道之后，G2、G4、G5 从「同一局域网内的机会」变成「互联网上任何人可尝试的路径」，因此 D3—D6 是 D1 的前置条件而非配套优化。

## 3. 决策

### D1 公网接入：Cloudflare Tunnel 取代 Tailscale

**链路。**

```
手机浏览器 / Android 壳
      │  https://<随机主机名>.trycloudflare.com
      ▼
Cloudflare 边缘（终结 TLS、DDoS 防护、无账号匿名隧道）
      ▲
      │  cloudflared 从 PC 主动拨出并保持的长连接（无需入站端口）
      │
cloudflared 本地进程
      │  http://127.0.0.1:8765
      ▼
aiohttp 单端口（/ws 命令面 + PWA 静态）
      │  鉴权门 → SidecarRouter.dispatch → application_service
      ▼
PC 上的 Sidecar、SQLite、项目文件
```

**为什么换。** Tailscale 要求用户在两台设备上分别安装客户端、登录同一账号，且两端必须同时在线。这带来一个第三方账号依赖和一套与产品无关的组网概念。Cloudflare Tunnel 把入站侧收敛成 PC 上的一个出站进程：用户不需要注册账号、不需要公网 IP、不需要开防火墙入站规则，也不需要理解「虚拟网络」是什么。手机侧零安装，浏览器直接打开 HTTPS 地址即可，正好满足手机语音对安全上下文的要求。

**进程归属。** V0.4.0 采用「应用托管，用户确认」：桌面端远程设置页提供「开启公网接入」开关，首次开启时由应用下载官方 `cloudflared` 可执行文件到用户数据目录，校验官方发布的哈希后启动为子进程，退出时关闭。仓库不打包该二进制，也不静默更新。已经自备命名隧道或自建反代的用户，保留手动填写入口地址的路径。

**只做 Quick Tunnel，不做命名隧道管理。** Quick Tunnel 零配置，代价是每次启动分配新主机名、带宽与可用性不作保证。命名隧道需要用户持有 Cloudflare 账号与自有域名，V0.4.0 在文档中说明这条进阶路径，不内建管理界面。

**已知限制（如实写入用户文档）。** 主机名每次重启都会变，二维码需重新生成；Cloudflare 将 Quick Tunnel 定位为临时用途，长期稳定使用应自备域名的命名隧道；隧道流量经由 Cloudflare 边缘，不再是「纯局域网、零第三方」。

### D2 监听面默认收窄到回环

`--serve` 默认绑定 `127.0.0.1`。局域网直连是新参数（`--lan`）显式开启的独立模式，开启后桌面端远程设置页常驻显示「局域网已暴露」状态，关闭即恢复回环。隧道模式始终走回环，手机不直连 PC 的局域网地址。

这条同时消灭 G1 与 G6 的一半：默认配置下，同一 Wi-Fi 下的其他设备根本到不了 `/ws`。V0.3.x 的局域网直连能力保留，但它从默认行为变成用户主动选择的降级路径。

桌面端 `serve.started` 事件需要携带入口的完整描述（协议、主机、端口、模式），二维码不再硬编码 `http://` + `ws://`。当前 `RemotePairingPanel.buildPairingUrl` 把 `http://` 与 `ws://` 写死在函数体里，隧道模式下会生成一个打不开的地址。

### D3 配对码失败限流

`claim()` 记录失败次数，按来源隔离。同一来源连续 5 次失败后封锁 60 秒，继续失败则退避翻倍，上限 30 分钟。触发限流写审计条目。封锁状态可以随配对状态一起持久化，重启不重置。

来源以连接为单位即可（`WSServerMode` 已有连接 key），隧道场景下所有流量都来自 `127.0.0.1`，按 IP 分会退化成全局限流，反而给出一条拒绝服务路径。

### D4 单码有效

`issue_code()` 在生成新码时清空全部未过期旧码。配套调整桌面端文案，把「重新生成」表述为「作废旧码并生成新码」，让用户知道手上的旧二维码立刻失效。

### D5 设备令牌生命周期

`_TokenEntry` 增加 `expires_at`，采用绝对有效期 30 天与空闲有效期 7 天二者取先到期者。`authorize()` 检查到期并记 `auth_failed: expired_token`。状态快照的 `version` 从 1 升到 2，`load_state()` 对缺少 `expires_at` 的旧条目按签发时间补算，避免升级后所有已配对设备立刻失效。

到期后手机端进入「授权已过期，请重新配对」状态，如实提示，不静默重连。

### D6 控制面只限回环

方法按来源分三级。

| 级别 | 方法 | 允许来源 |
| --- | --- | --- |
| 免鉴权 | `remote.pair` | 任意（受 D3 限流约束） |
| 控制面 | `remote.issue_code`、`remote.list_devices`、`remote.revoke`、隧道开关 | 仅回环（桌面端 stdin 路径与 Tauri 侧） |
| 业务面 | 其余全部方法 | 有效设备令牌 |

远程连接调用控制面方法返回 `forbidden_scope` 并记审计。`remote.claim_control` 与 `remote.release_control` 描述的是手机取用播放控制权，属于业务面，不在收窄之列。

判定依据采用连接来源，不用请求体里客户端自报的字段。

### D7 隧道 URL 不是秘密

`*.trycloudflare.com` 主机名会进入证书透明度日志，任何人在公开日志里都能枚举到新出现的主机名。主机名因此等价于公开信息，不能承担任何访问控制职责。这条决定了三件事。

PWA 静态目录只允许包含构建产物，不得写入任何用户数据、账号信息或项目内容，需要在打包流程里加一道校验强制这一点。

用户文档必须写明：地址被他人看到不等于被接入，真正的防线是配对码与设备令牌；同时不要在公开场合张贴二维码截图。

隧道模式下未配对连接唯一能调用的方法就是受限流的 `remote.pair`。

### D8 登录页标语

`desktop/src/ui/gate/AccountGate.tsx:32` 的 `一间房，两盏灯。` 改为 `一条会话，两条工作轨。`。新标语对应「角色负责对话、助手负责工具」的并行结构，与 V0.2.0 时期的空间隐喻无关。

`desktop/src/ui/workspace/Workspace.tsx:21` 的注释同样引用了旧标语，一并更新。`docs/design/旧版/` 下的历史文档记录的是 v0.2.0 时代的视觉方案，保持原样，不回改。

## 4. V0.4.0 变更清单

**Sidecar 与协议**

1. `ws_server.py`：监听地址改为构造参数，默认 `127.0.0.1`；`--lan` 时才是 `0.0.0.0`。
2. `ws_server.py`：鉴权门把连接来源传给 `authorize()`，实现 D6 的三级判定。
3. `pairing.py`：`claim()` 增加失败计数、封锁与退避（D3）。
4. `pairing.py`：`issue_code()` 清空未过期旧码（D4）。
5. `pairing.py`：`_TokenEntry` 增加 `expires_at`，`authorize()` 检查到期；`export_state()` 版本升到 2，`load_state()` 兼容版本 1（D5）。
6. `application_service.py`：`_remote_issue_code` / `_remote_list_devices` / `_remote_revoke` 加来源校验，非回环返回 `forbidden_scope`；同步修正 `_remote_issue_code` 的 docstring。
7. `application_service.py`：审计条目补 `pairing_code_issued`、`pairing_rate_limited`、`scope_denied`、`tunnel_started`、`tunnel_stopped`。
8. `__main__.py`：新增 `--lan` 参数；`serve.started` 事件携带入口协议、主机、端口与模式。
9. 新增隧道管理模块：下载并校验 `cloudflared`、启动与停止子进程、解析分配的主机名、把真实状态（下载中、启动中、已就绪、失败原因）上报为事件。失败不得伪装成就绪。
10. 隧道进程与 Sidecar 同生命周期：Sidecar 退出时关闭隧道进程，不留孤儿。

**桌面端**

11. `lib.rs`：`REMOTE_SERVE_PORT` 保持不变，启动参数随用户设置切换 `--lan`；新增隧道开关与状态透传。同步更新 `remote_serve_port_matches_frontend_qrcode_payload` 测试。
12. `RemotePairingPanel.tsx`：`buildPairingUrl` 按 `serve.started` 上报的协议生成地址，去掉写死的 `http://` 与 `ws://`。
13. `RemotePairingPanel.tsx`：新增公网接入开关、隧道真实状态、局域网暴露提示、令牌到期时间展示。
14. `RemotePairingPanel.tsx`：「重新生成配对码」文案改为说明其作废旧码的语义。
15. `AccountGate.tsx:32`：标语改为「一条会话，两条工作轨。」。
16. `Workspace.tsx:21`：注释同步更新。
17. 移动端 `PairPage.tsx` 与 `wsClient.ts`：地址校验接受 `https` / `wss`，配对失败提示区分限流、过期与非法码。

**文档与打包**

## 5. 验收标准

以下各项在 V0.4.0 发布前必须真实执行并留证。

- 默认启动下 `--serve` 只监听回环；用另一台局域网设备访问 PC 的 `:8765` 连接被拒。
- 开启 `--lan` 后局域网可连接，桌面端出现暴露提示；关闭后提示消失且连接中断。
- 公网隧道可用：手机在蜂窝网络（非同一 Wi-Fi）下打开隧道地址，HTTPS 加载，语音入口可用。
- 隧道地址与配对码出现在二维码中，扫码后完成配对并进入对话；PC 重启后隧道主机名变化，旧二维码失效且界面如实提示。
- 连续提交 5 次错误配对码后该来源被封锁，后续正确配对码在封锁期内仍被拒，解锁后恢复正常；审计留有记录。
- 反复生成配对码时，任意时刻只有最后一枚有效，之前生成的码全部返回过期或无效。
- 已配对设备调用 `remote.issue_code`、`remote.list_devices`、`remote.revoke` 全部被拒并返回 `forbidden_scope`；同样的调用从桌面端成功。
- 手工把某设备令牌的 `expires_at` 调到过去，该设备下一次请求被拒并提示重新配对；桌面端仍可正常撤销。
- 撤销设备后该设备立即断连，重连被拒。
- 隧道进程被外部杀死后，桌面端显示真实失败状态，不显示「已连接」。
- PWA 静态目录校验在构建期拦截用户数据文件。

## 6. 明确不做

- 不内置自签证书，不建议用户忽略浏览器证书警告。
- 不运营发布方自有的中继、信令、推送或语音转发服务器。
- 不在无鉴权的端口上暴露命令执行。
- 不把隧道 URL 或二维码当作访问控制。
- 不实现命名隧道的账号绑定与管理界面。
- 不打包 `cloudflared` 二进制进仓库或安装包。
