# HSR Partner Harness V0.3.0—V0.6.0 迭代计划

## 总体安排

- **V0.3.0：搭档扩充版。** 只接入“流萤 × 萨姆”“三月七 × 第四面镜”及对应角色卡、助手设定、资源、语音和选择入口，不夹带下述性能与记忆改造。
- **V0.4.0：正确性与度量版。** 修复三个已确认问题，建立 token、缓存、延迟和 prompt 形状的真实观测能力，并完成两个技术 spike。
- **V0.5.0：上下文与性能完整版。** 上线持久化上下文投影、会话摘要、跨聊天角色记忆、流式链路优化和审批语义收敛，尽可能落实六份文档中经代码核实成立的优化。
- **V0.6.0：角色创作与 SillyTavern 兼容版。** 在 V0.5.0 的上下文与记忆能力上增加分层角色卡、世界书、提示词预设和宏装配，并支持把 SillyTavern 文件单向导入后直接用于对话和任务委派。

V0.4.0 必须从 V0.3.0 的干净发布基线开始。当前工作区已有大量未提交改动，后续不得使用 `git add -A`，也不得把 V0.3.0 的搭档接入和 V0.4.0 优化混进同一提交。

## V0.3.0：只完成新搭档接入

- 新增流萤、三月七角色卡，以及萨姆、第四面镜助手设定；为三组搭档分别提供 YAML、主题、头像/图标和可用语音配置。
- 增加搭档目录与选择入口。新建聊天时选择搭档，已有聊天继续以自身 `pair_id` 恢复，切换项目或重启后不串角色。
- 三组搭档共用现有委派、审批、编程引擎、标题、语音和双空间消息管线，不为新角色复制业务逻辑。
- V0.3.0 不实施 `target` 修复、usage 指标、投影摘要、跨聊天记忆、delta 合并、delegate tool call、EP v1 或 Pi。
- 验收覆盖三组搭档的角色对话、直发助手、角色委派、结果回流、语音身份、重启恢复和资源打包；同步所有正式版本号并生成 NSIS 安装包。

## V0.4.0：正确性、观测与技术门控

### 1. 修复确定问题

- `recent_roleplay_context()` 只接收角色消息以及 `user + target=character`；旧数据中 `target=None` 暂按角色消息兼容。向助手发送的任务不得进入角色历史。
- 使用账号级 `app_state` 保存 `last_active_conversation_id`。每次实际选中聊天时更新，启动时校验账号归属和未归档状态，无效才回退到最近活跃聊天；不改变 `updated_at` 的排序语义。
- `_message()` 改成数据库写入成功后再追加 `_history`、触发监听器和推送事件。写库失败时本轮立即失败，不再调用模型。

### 2. 建立真实度量

- 对 DeepSeek 流式请求启用 usage 返回，归一记录 input、cache hit、cache miss、output、reasoning token；保留供应商原始 usage JSON，避免定价或字段变化后无法重算。
- 新增 `turn_metrics`，记录回合、账号、聊天、搭档、模型、用户选择的思考档位、token、首字延迟、总耗时、历史体量、距上一轮时长、时段和稳定前缀哈希。
- 对 provider 可见的稳定 system 与 tool schema 做确定性序列化和前缀指纹；跨轮记录首个变化区域，区分真正的请求变化和本地 UI 元数据变化。
- 增加本地开发诊断命令，能够查看最近回合指标和本轮实际发送的消息结构；不显示 API Key，也不保存或展示 reasoning 原文。
- 建立 prompt golden snapshots，覆盖普通聊天、向助手直发后再与角色聊天、角色委派、执行结果回流和三组搭档切换。

### 3. 完成两个 spike

- **Reasonix EP v1：**验证工具调用是否可阻塞、能否等待数秒级异步审批、sidecar 与 Python 的 IPC 形态。结果形成明确 go/no-go。
- **Delegate tool call：**用实际 DeepSeek 模型和前端提供的全部思考档位测试自然语言正文与工具调用能否稳定共存。只有委派成功率不低于现有 JSON 协议、错误委派不增加，且首字延迟或 output token 至少改善 10%，才进入 V0.5.0。
- V0.4.0 收集连续会话、冷启动、不同闲置时长的数据，据此冻结 V0.5.0 的上下文阈值。缺少足够数据时采用默认值：历史投影在约 48k token 触发，压缩后逐字尾控制在约 24k，并至少保留最近六个完整往返。

## V0.5.0：持久上下文、长期记忆与性能收敛

### 1. 持久化上下文投影

- canonical 消息记录始终追加且不重写；新增 `conversation_projections` 保存投影版本、结构化摘要、覆盖到的消息 ID 和生成时间。
- 角色请求固定为：稳定角色前缀 → 当前投影摘要 → 最近完整逐字往返 → 任务/结果/运行上下文 → 当前用户消息。
- 摘要使用固定槽位：已确认事实与偏好、角色状态与情绪、关系和关键事件、共同完成的工作、未兑现承诺与待续话题、世界设定增补。
- `CharacterResultSummary` 的真实工作结论直接进入“共同完成的工作”，不额外生成重复气泡。
- 投影在完整回合后异步生成。候选必须小于源内容；生成期间消息发生变化则丢弃候选，本代不重试，下一完整回合再生成。
- provider 请求只保留角色、用户和必要摘要字段；`reasoning`、时间戳、审批记录、工具 UI 元数据和其他本地字段不得回流模型。
- 重启后恢复同一投影版本，避免每次启动重新滑窗并破坏缓存形状。

### 2. 跨聊天角色记忆本

- 新增账号与 `pair_id` 作用域的角色记忆，记录内容、来源聊天、更新时间和类别。
- 在投影更新时提取长期稳定的称呼、偏好、约定、关系变化和共同完成的工作；不引入向量数据库。
- 设置中心提供查看、修改和删除入口，不允许不同账号或不同搭档相互读取记忆。
- 会话中途产生的记忆更新先作为动态块附在当前用户回合，等新聊天或下一投影版本再折入长期记忆区域，减少稳定前缀抖动。

### 3. 流式与角色输出优化

- Sidecar 出口按 `message_id + channel` 以约 20ms 窗口合并连续 delta，再分配事件序号；终态、错误、审批和跨消息切换立即 flush，保持现有单调序号与重新水合协议。
- 若 V0.4.0 的 delegate spike 通过，角色正文改为直接自然语言流，委派通过稳定的 `delegate` tool schema 输出；解析失败继续以纯台词安全收尾。未通过则保留当前 JSON 协议。
- 为角色请求加入 429、503 和超时的两次退避重试，并展示“服务繁忙”状态；不做静默备用端点切换。
- 原始 usage 与价格配置分离，历史成本按当前价格重新计算，不把某一时期的 DeepSeek 单价写死在指标表中。

### 4. 审批链收敛

- EP v1 spike 通过时，Reasonix 工具调用在执行前交给 Python 的 `sandbox → risk_rules → ApprovalManager`，并尽量使用结构化工具参数；Codex 与 Reasonix 共用同一审批语义。
- Spike 未通过时，Reasonix 使用强制 ask 的协议模式确保每个工具机会都到达 Python，再由当前三种审批模式自动允许、审查或询问用户；不能新增额外的无条件人工弹窗。
- 不改变现有三种审批模式，不做批量审批，不把业务权威移入 Reasonix sidecar。

### 5. 接口和数据变化

- `StateStore` 增加最后活动聊天、回合指标、上下文投影和角色记忆的读写接口，并通过逐级 SQLite migration 升级。
- `DialogueRequest` 增加投影摘要、长期记忆和指标关联信息；模型 adapter 返回统一 usage/latency 结果。
- Sidecar 协议增加本地诊断查询和角色记忆 CRUD 命令；现有消息、工具和回合事件保持向后兼容。
- `providers.py` 继续作为供应商识别、usage 归一、上下文元数据和价格配置的单一入口，并保留 DeepSeek-Reasonix 的来源说明。

## V0.6.0：角色创作与 SillyTavern 兼容

### 1. 版本目标与兼容边界

- 把角色定义拆成角色本体、世界设定、表达规则、提示词顺序和运行时上下文，避免继续扩充单一 system prompt。
- 支持单向导入 SillyTavern Character Card、World Info 和 Prompt Manager 预设。导入后转成 HSR Partner Harness 的内部模型，由 Python Sidecar 统一组装请求。
- V0.6.0 不向 SillyTavern 回写或导出文件，也不嵌入 SillyTavern 前端、Node 运行时和扩展市场。
- 兼容目标覆盖角色卡及配置中的声明式能力；不执行任意 JavaScript、第三方插件代码或 STScript。遇到这类内容时保留原始字段，在导入报告中列出未启用项，其他可兼容部分照常导入。

### 2. SillyTavern 文件导入

- 支持 Character Card v3 JSON 和带角色卡元数据的 PNG；同时兼容常见 v2 字段，并统一归一到内部 v3 语义。PNG 头像提取后作为角色资源保存。
- 导入角色本体字段：`name`、`description`、`personality`、`scenario`、`first_mes`、`mes_example`、`alternate_greetings`、`system_prompt`、`post_history_instructions`、`character_book` 和 `extensions.depth_prompt`。
- 支持独立世界书 JSON，以及角色卡内嵌和 `extensions.world` 引用的世界书。外链世界书缺失时允许先导入角色，并明确标记缺失依赖。
- 支持 Prompt Manager 导出的提示词预设，读取提示词条目、`prompt_order`、启用状态、消息角色、注入位置、assistant prefill 和声明式 RegexBinding。
- 导入时展示预览与兼容报告，列出将创建的角色、世界书、提示词模块、开场白、未解析字段和缺失依赖。用户确认后才写入当前账号的数据目录。
- SillyTavern 角色卡只定义角色侧。导入时由用户选择一个现有助手与其组成搭档；未选择时使用当前搭档的助手。助手身份、审批和执行能力继续来自 HSR Partner Harness，不读取角色卡中的工具执行指令。
- 导入角色默认不带可用语音。用户可在搭档设置中选择或创建音色，缺少音色只关闭朗读，不影响文字对话。

### 3. 内部角色卡与提示词槽位

- 新增可持久化的角色资料、世界书、提示词预设和导入搭档模型，按账号隔离。原有白厄、流萤、三月七 YAML 继续可用，并通过同一内部结构参与组装。
- 固定提示词槽位及顺序：世界书前置 → 主规则 → 世界书后置 → 角色描述 → 性格 → 场景 → 用户身份 → 自定义模块 → 示例对话 → 会话投影与近期历史 → 历史后指令 → 当前用户消息 → assistant prefill。
- 角色卡的 `system_prompt` 只覆盖主规则槽位，不覆盖 HSR Partner Harness 的角色/助手职责边界、委派结构和真实结果回流规则。
- `post_history_instructions` 放在近期历史之后，承担当前场景中的表达纠偏；`depth_prompt` 按配置的深度插入，但不得进入或改写历史消息。
- 相邻且语义位置相同的 system 消息在发送前合并，减少结构开销。最终请求继续进入 V0.4.0 的 prompt 诊断和 V0.5.0 的前缀指纹、token 预算与投影系统。

### 4. 世界书动态注入

- 世界书条目支持主关键词、次关键词、启用状态、优先级、插入位置、扫描深度、最少激活次数和递归激活。
- 每轮只扫描 V0.5.0 投影摘要、保留的逐字尾和当前输入。命中条目按优先级和原始顺序稳定排列，再进入世界书前置或后置槽位。
- 表层设定与深层秘密可放入不同条目。没有关键词或剧情条件命中时，深层条目不进入模型请求。
- 递归展开设置最大轮次和本轮世界书 token 预算；达到上限时保留优先级更高的完整条目，不截断单条设定。
- 世界书作用域分为账号共享、角色专属和当前聊天专属。多个作用域命中同一条目时按条目 ID 去重，聊天专属版本优先。

### 5. 宏与提示词模块

- 第一批宏覆盖 `{{char}}`、`{{user}}`、`{{lastUserMessage}}`、日期时间和当前项目等只读数据，以及 `setvar`、`addvar`、`getvar`、`incvar` 这组 Prompt Manager 常用变量宏。
- 宏严格按 `prompt_order` 展开，每次请求使用独立变量环境：先清空、再按顺序写入和读取，不把提示词变量误当成跨聊天角色记忆。
- 提示词模块保留启用开关、消息角色和先后依赖，允许用户在设置中查看最终顺序、临时停用模块，并预览宏展开后的 provider 可见内容。
- Assistant prefill 作为提示词集合的最后一条 assistant 消息发送。供应商不接受该形状时，关闭 prefill 并给出明确兼容提示，不私自改写成另一种指令。
- RegexBinding 只支持对最终正文的声明式匹配、替换和显示折叠。原始角色正文仍按正常消息落库，正则不得改写工具事件、审批内容或执行回执。

### 6. 与 V0.5.0 上下文和记忆的衔接

- 角色卡、启用的固定提示词模块和稳定工具 schema 构成缓存稳定前缀；世界书命中、作者注记、投影摘要、长期记忆更新和当前输入放在后续动态区域。
- 世界书条目只在命中时进入当轮请求，不写入 canonical transcript。某项设定经过对话确认后，可由 V0.5.0 的投影摘要或角色记忆本长期保留。
- 示例对话作为低频稳定槽位参与 token 预算。预算不足时先减少示例，再裁剪低优先级世界书，最后才触及 V0.5.0 保留的最近完整往返。
- 切换角色卡、世界书、提示词预设或模块开关会创建新的 prompt 配置版本，并明确记为一次预期缓存换代；同一版本内必须保持确定性序列化。
- 作者注记支持当前聊天临时内容和固定注入深度，用于调整场景或语气；它不进入跨聊天记忆，除非用户明确保存为角色记忆。

### 7. 前端与使用流程

- 搭档目录增加“导入 SillyTavern”入口，依次完成选择文件、兼容预览、选择助手、确认导入和开始聊天。
- 角色详情页展示角色描述、开场白、备用开场、关联世界书和提示词预设；允许为新聊天选择一条开场白。
- 设置中心增加角色资料、世界书、提示词模块和作者注记四个入口。第一版以查看、启用、停用和编辑已导入内容为主，不建设完整的 SillyTavern 创作器或插件市场。
- 开发诊断视图显示各提示词槽位的 token 体量、世界书命中原因、宏展开结果、被预算排除的条目和最终消息顺序，沿用现有本地诊断边界。

### 8. 接口和数据变化

- `StateStore` 增加角色资料、世界书及条目、提示词预设及模块、导入搭档、聊天作者注记和 prompt 配置版本的读写接口，并通过逐级 SQLite migration 升级。
- `PairConfig` 增加内部角色资料引用、世界书引用和提示词预设引用；仓库内置 YAML 与账号导入资料通过统一的 resolver 加载。
- 新增导入器接口，分别解析 Character Card、PNG 元数据、World Info 和 Prompt Manager 预设，输出统一的导入预览、兼容警告和归一化结果。
- `DialogueRequest` 接收已经解析完成的 prompt collection 和世界书命中结果；Dialogue adapter 只负责确定性序列化和供应商调用，不在适配器里重复实现导入逻辑。
- Sidecar 协议增加导入预览、确认导入、角色资料查询、世界书管理、提示词模块管理和作者注记命令；已有聊天与搭档协议保持兼容。

### 9. V0.6.0 验收标准

- 使用《SillyTavren的优点.md》引用的白厄 Character Card v3 和“可待·从头越 Agent版”预设作为主要兼容样例，能够完成导入、选择助手、新建聊天和真实 DeepSeek 对话。
- 角色描述、性格、场景、开场白、示例对话、历史后指令、depth prompt、内嵌与外链世界书进入正确槽位；表层和深层关键词测试不会提前泄露未命中的秘密。
- `prompt_order`、模块开关、变量宏、assistant prefill 和声明式 RegexBinding 的结果与兼容样例预期一致；未支持的脚本能力出现在导入报告中，不能静默忽略。
- 导入内容按账号隔离，三组内置搭档不受影响；删除导入角色不得删除原始导入文件之外的聊天和共享世界书。
- 同一 prompt 配置版本重复组装得到相同的 provider 可见前缀；切换模块或世界书后只发生一次可解释的版本换代。
- 世界书、宏和预设加入后，角色仍不能直接执行文件或命令；委派、助手执行、审批和真实结果回流继续走原有业务链。

## 测试与发布标准

- **V0.4.0：**三个确定问题均有回归测试；不同 `target` 不串历史；数据库失败不产生幽灵消息；最后打开聊天可恢复；DeepSeek usage 归一正确；稳定前缀 golden snapshots 不漂移。
- **V0.5.0：**覆盖投影生成、陈旧候选、重启恢复、摘要槽位、reasoning 净化、跨账号/跨搭档记忆隔离、记忆 CRUD、结果回执入摘要和阈值边界。
- **V0.6.0：**覆盖 Character Card JSON/PNG、内嵌与外链世界书、Prompt Manager 顺序、宏环境、assistant prefill、RegexBinding、导入依赖缺失、账号隔离和内置搭档回归。
- 连续热会话中，投影未换代前稳定前缀哈希必须 100% 不变；排除首轮、长时间闲置和投影换代后，DeepSeek 缓存命中目标为 90% 以上。
- Delta 合并后 Sidecar 跨进程增量事件数至少下降 50%，额外首字延迟不超过 25ms，取消、聊天和编辑在长任务期间继续响应。
- 审批验收覆盖 Codex、Reasonix以及三种审批模式；越界操作仍由 Python 拒绝。
