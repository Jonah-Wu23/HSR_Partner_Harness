## 1. 复查结论与修复

### 1.1 V13a（手机语音与审批状态呈现）

外派模型报告 5 项，主控核实后：**3 项属实并修复，2 项不成立**。

属实（`14ad18e`）：
- **PTT 启动必炸**：`mobileStore.ts` `startVoiceCapture` 未 `return result`，接口 `Promise<{session_id} | void>` 的 `| void` 放过类型检查；`useVoiceCapture` 每次启动必抛「服务端未返回语音会话 ID」，手机端按住说话在真实链路不可用。修复：返回结果、收紧接口、非空闲早退由静默 return 改为如实抛错。
- **手机审批发非法决策值 `"approve"`**：后端 `ApprovalDecision` 仅 `allow / allow_for_conversation / deny`（`core/contracts.py:428`），真实链路上手机批准必被 `invalid_decision` 拒绝。修复：`ChatPage.tsx` 改发 `"allow"`；`ApprovalCard` 决策标签补 `allow / allow_for_conversation`。
- **仲裁失败伪造对端决策（违反 Let It Fail）**：`resolveApproval` catch 曾用本端入参顶替已决记录（对端真实 deny 会显示成本端 approve）。修复：优先保留 `approval.resolved` 事件已写入的真实记录；事件未到时从服务端错误文案「审批已由 <resolved_by> 应答（<decision>）」提取；解析不到则如实不补已决卡片。

不成立（记录理由）：**「stopping 卡死」**——`end_session` 成功路径必发 `is_final` 回调且与响应同 WS 有序，失败路径 catch 复位；**「is_final 提前置空导致漏发 ptt_stop」**——`is_final` 只能由 `ptt_stop` 驱动的 `end_session` 发出，120 秒 watchdog 走 `cancel_session` 静默取消不发事件。

### 1.2 V13b（会话切换水合）

- **属实并修复**：设置页回退 pair 音色读 `currentConversationId`（Sidecar 全局指针）而非本窗口 `activeConversationId`，多标签/多窗口分叉时读错会话（`presenters.ts`）；`AppShell` 关闭设置中心或普通打开时不清空 `voiceCardFocus`，角色库直达预选卡跨会话残留。
- 遗漏项（记录未改）：`actions.ts` `createConversation` 未暴露契约已支持的 `characterCardId` 可选参数——当前主链路用 `selectActiveCard` 间接下发已闭环，补参数而无调用方属于死代码，列为建议。
- 观察项：聊天工作区角色名与头像仍映射自内置 pair，符合既定装配边界。

### 1.3 V13c（双端失败语义）

- 桌面端全部新错误码 surfacing 完整，未发现吞错；手机端语音错误经 `capture.error` 进 `role="alert"` 展示。
- **属实并修复**：`sendAudioChunk` 失败（如 `voice_audio_seq_gap`）此前只 `console.error`，真实错误被后续停止流程冲掉；现写入 `capture.error` 并继续抛出。
- **观察项（记录未改）**：后端 `approval_already_resolved` 响应体仅有 `code + message`，未落实契约 §6 承诺的结构化 `{decision, resolved_by}`，手机端对错误文案的正则提取与之耦合。**该定约缺口属于 Python 侧，不在本分支范围**，已列遗留建议。
- 否决项：移动端获批按钮曾被报告「缺少 allow_for_conversation 按钮」——属产品取舍，未扩展，列为建议。

### 1.4 V14（视觉一致性，含与 `docs/design/web-prototype/` 的出入）

复查列出三组差异：RemotePairingPanel（V0.3.4 遗留组件）内联样式与新 UI 组件语言不一；四个新 UI 之间色彩 fallback 写法不一、主色选型不一（角色库/导入导出/语音区用蓝色 `--accent`，创作页绑 `--gold`）；与原型的信息架构出入（模态 vs 全屏页、页签 vs 一级页、双栏无预览 vs 三栏预览、虚拟滚动 vs 分页、卡片标签行省略等）。

**用户决策（2026-08-29，口头指令优先于计划 §0.3 的视觉自主权条款）**：保持现有设计，**严禁任何视觉改动**。全部差异转为观察项入库，视觉回改不执行。主控曾提议的三套对齐方案（局部换色 / 全套换新界面 / 全局换原型调色板）未被采纳。

## 5. 离线测试

- desktop：`tsc -b --force` 0 错误；全量 vitest **252/252**（19 文件）；`npm run build` 通过。
- mobile：`tsc --noEmit` 0 错误；全量 vitest **106/106**（13 文件）。
- Python：全量 pytest **665 passed / 5 skipped**（逻辑轨改动未触碰）。
- Rust：`cargo test` **15/15**。
- **稳定性说明（如实记录）**：desktop 全量在某几轮出现 `CharacterVoiceSection.test.tsx` 的单测试偶发失败（三个不同用例在不同轮次命中），单独运行均稳定通过。经查根源为**真实的事序竞态**：`prefix` 由 `cardDetail` 到达后的 effect 种子化为默认前缀「card」，空前缀合法（按钮可点），测试点击落在种子化之前则 `voiceCardCreate` 收到 `{}`；同理该 effect 会把 `createMode` 重置为 clone，design 用例的切换点击若在其之前会输入框出现又消失。修复方式（断言强度不变）：测试先等待 `prefix-input` 值种子化为「card」（即 effect 已落定）再切模式/点击，创建按钮点击改为「仅可点时点击、命中即停」辅助函数，并将一处等待超时放宽至 5s（已注明原因）。根治后连续 6 轮全量验证全绿（252/252）。该竞态在真实产品中无影响——人类点击不可能落在 effect 落定前的微秒级窗口，且产品语义上「前缀缺省可提交」为设计行为。

## 6. 遗留与建议（不在本分支改）

1. **Python 侧**：`approval_already_resolved` 响应体补充契约 §6 承诺的结构化 `{decision, resolved_by}`，手机端可弃用文案正则（`application_service.py` 的 ServiceError 目前仅 message+code）。
2. `actions.ts` `createConversation` 暴露 `characterCardId` 可选参数（契约已支持，当前用激活卡间接下发）。
3. 手机端是否提供「本会话内允许」（`allow_for_conversation`）按钮——产品决策。
4. `output/playwright/` 下的 V0.3.4 遗留截图（`desktop-*.png`、`mobile-*.png` 非 v035 前缀）未纳入本验收，归属其原阶段。
5. 视觉对齐（原型调色板/组件语言迁移）不再执行，相关差异作为 V0.4.0 原型迁移的观察输入保留。

## 8. 验收结论
