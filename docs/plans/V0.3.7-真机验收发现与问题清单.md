## B. 构建链缺陷（已定位并跑通，流程需固化到文档）

| # | 问题 | 根因与修复 |
| --- | --- | --- |
| B1 | 改前端后 APK 里行为不变 | **前端资产在编译期嵌入 .so**（`generate_context!`），APK `assets/` 目录只是摆设——改前端必须重编 aarch64 .so。真机以 devtools 实证（页面加载 `index-BpPPlGw7.js` 而 APK assets 是新的） |
| B2 | 重编 .so 后壳加载 devUrl 1420 白屏 | 裸 `cargo build` 缺 `tauri/custom-protocol` feature → `dev: cfg!(not(feature="custom-protocol"))` 为真，不嵌入 frontendDist。须 `--features tauri/custom-protocol` |
| B3 | 重编报 `WRY_ANDROID_PACKAGE is not set` | wry build.rs 需 `WRY_ANDROID_PACKAGE`/`WRY_ANDROID_LIBRARY`/`WRY_ANDROID_KOTLIN_FILES_OUT_DIR`（输出到 gen/android generated 目录） |
| B4 | 前端更新不进 APK | 除 .so 重编外，需同步 mobile dist → `gen/android/app/src/main/assets/`，且 gradle 需 `--rerun-tasks`（assets merge 对 cp 覆盖不敏感） |
| B5 | 语音服务地址配置错误致音色生成 404/EOF | `voice.base_url` 必须是**专属地域端点**（如 `https://{workspace}.cn-beijing.maas.aliyuncs.com/api/v1`，.env `DASHSCOPE_BASE_URL`），通用域 `dashscope.aliyuncs.com` 路由 404；配置正确后 provision 一次成功（原始 2.27MB 参考音频完整上传） |

## C. 🔴 真机验收未过项（V0.3.8 待办，均有证据）

### C1 后台/锁屏事件保活失败（#10 核心未过）
- 现象：手机退后台（home）后，桌面侧消息与回复事件**不达手机**（回前台聊天页无新消息、无断连横幅）；引擎因此收不到 turn 事件，任务完成本地通知从未发出（NotificationService 日志无 phm_* post；通知栏仅前台服务常驻条目 1001）。
- 证据：后台期间 `visibilityState=hidden` 正确；stdin `chat.submit` 触发的 turn completed 桌面侧正常，手机无感知；`dumpsys notification` 无任务通知。
- 判断：WsForegroundService 保住了**进程**，但 WebView 退后台后 JS/WS 事件通道中断——前台服务方案（契约 §9.2 (b) 落地版）**不足以**支撑"锁屏收通知"目标。契约 §9.2 spike 的选型判据（锁屏 30 分钟保持 WS）真机实测给出否定结论，需架构级方案（WebView 后台策略/原生 WS 常驻/其他），归 V0.3.8。
- 附带：webview 后台冻结还叠加 B 系列（WebView 150 白屏）与 C2。

### C2 移动端朗读播放即黑屏（渲染进程崩溃）
- 现象：桌面 TTS 合成正常（专属音色，chunks 推送完成），手机端开始播放瞬间 WebView 渲染层崩溃（进程活、surface 黑、无 FATAL 弹窗）。
- 证据：`02:56:08 chromium services/audio/sync_reader.cc: ASR: No room in socket buffer: Broken pipe (32)` —— AudioContext 播放启动瞬间音频管道断裂。
- 判断：WebView 150（MIUI 定制）AudioContext 播放 PCM 的渲染进程级缺陷或兼容问题；修复需设备迭代（播放路径改造/降级 <audio>、或验证 WebView 更新），归 V0.3.8。
- 影响：#9 语音主路径（移动端发声）未闭环；桌面端朗读正常（用户实测）。

### C3 消息队列期间前端无操作能力（用户报告）
- 现象：手机新发的消息进入队列（busy/排队）后，前端无法显示该消息的完整状态，也无法编辑/删除/立即插入；界面"点了没反应"。
- 判断：队列语义与前端呈现/操作能力缺口——排队中的用户消息应可见（已发送/排队态），并支持撤回/插队等既有队列命令（queue.withdraw/queue.edit/queue.prioritize 存在于协议但移动端 UI 未接）。桌面端同缺陷（用户确认"桌面端问题也非常严重"）。归 V0.3.8，需产品口径 + 双端 UI。

### C4 会话任务链卡死
- 现象：协作委派（角色形成委派卡）后任务永久"运行中"不结束、不触发审批请求（approval.requested 零次）；后续消息排队不前进（多次 chat.submit 无回复，task.cancel 才释放）；出现 turn cancelled（assistant）与重复会话记录（两条"真机对话一"）。
- 判断：serve 模式下委派执行链（角色委派→app-server 工具执行→审批 gate）存在挂起面：未触发审批也未完成。契约 §5/额度走查 P1 链路桌面已验证，serve+手机 origin 场景暴露差异。归 V0.3.8 深查。

### C5 手机黑屏/白屏复发（稳定性）
- 现象：验收全程多次黑屏/空白根路由（进程活、页面空白），force-stop 重启恢复；高频发生在后台返回与播放场景。
- 判断：与 C2 同源的 WebView 150 稳定性问题 + 后台冻结（C1）叠加。归 V0.3.8。

### C6 会话重复创建
- 现象：列表出现两条同标题「真机对话一」（02:35 与 02:56），后一条带「委派」标签。疑似手机端在某次操作中触发了重复会话创建或桌面 current_conversation 漂移。归 V0.3.8 核对创建路径幂等性。

## E. 过程备注（供复盘）
- install -r 覆盖安装时 MIUI 延迟 kill 旧进程（installPackageLI）曾撞上朗读播放被误判为应用崩溃——装机后先 force-stop 再使用可规避。
- 桌面驱动 WS 探针可复现 remote-only 通道验证（订阅后收 chunk/事件）——后续 TTS 链路回归可复用。
- 命令等待应采用响应式轮询（盯 logcat/log 尾部目标事件），避免固定 sleep。
