## 0. 总则

### 0.1 已确认决策（2026-09-02 与用户对齐，双轨全程有效）

1. **开工基线**：V0.3.5 已验收，直接以 main 现状开工，不安排 V0.3.6 前置修复；本阶段真机与集成中新发现的缺陷按偶数版本号约定归 V0.3.8。
2. **阶段范围**：保持路线图全量——酒馆双向兼容（v2/v3 JSON 补强＋PNG 双向）、mufy 高级角色系统与世界书、手机远程 P2（Android 壳＋本地通知＋电源保障）三块都在本阶段交付。
3. **Android 条件**：用户有 Android 真机并可配置 SDK/NDK 工具链，P2 按完整交付规划，含真机主路径验收。
4. **装配深度**：参考 `E:\Tavern\SillyTavern` 的真实实现方式，按契约 §9 全量装配，语义交给角色模型执行；仅事件池/时间线中「明确轮次、明确时间」的确定性触发由运行时按声明执行，代码不猜测语义条件。
5. **世界书激活范围**：实现核心子集（见 §2.2），概率、递归激活、互斥组、sticky/cooldown 时效、min activations、`@@` 装饰器等 SillyTavern 扩展语义存而不运行，在兼容报告中如实列出。
6. **token 预算**：卡声明的书级 `token_budget` 生效（未声明时对齐 SillyTavern 默认 25% 上下文预算）；全局上下文预算、压缩与记忆仍归 V0.3.9。
7. **宏展开**：只展开数据宏（`{{char}}`、`{{user}}` 等白名单）；变量宏（setvar/addvar/getvar）与脚本宏（STScript）一律不执行，含此类宏的内容原样保留并在兼容报告标注「未展开」。
8. **Android 常驻策略**：壳内以前台服务保持 WS 长连接，锁屏/后台可收审批与任务完成通知；代价是通知栏存在常驻条目；连接被系统杀死时在壳内如实显示断连，不伪造在线。

### 0.2 双轨并行方式

沿用路线图第 5 节与 V0.3.5 经验：本阶段由「强逻辑 AI」与「强视觉 AI」双轨并行推进。强逻辑 AI 先冻结本阶段数据契约、状态枚举和事件含义（见第 2 节），强视觉 AI 基于冻结契约和样例数据并行施工，不等待全部后端逻辑完成。集成时必须接入真实 Sidecar 状态，模拟数据只能帮助视觉开发，不能作为验收证据。

分支形态沿用：`v0.3.7-logic-ai` 与 `v0.3.7-visual-ai` 双分支（视觉轨基于逻辑轨契约冻结提交起步），视觉轨内部的 worktree 拆分由视觉轨自主决定。阶段收尾时保证视觉分支包含逻辑分支全部提交，一次 PR 合入 main。

### 0.3 不可违背的仓库准则

- **Let It Fail**：PNG 读写、导入导出、世界书装配、通知投递、电源检测、真机连接的失败必须保持真实失败与原始错误，不合成成功、空结果或伪造回执。诊断和真实验收使用真实配置、真实服务、真机与真实 SillyTavern 环境。
- **Let It Go**：世界书关键字命中只决定该条目是否注入角色提示词，不得用于判断用户意图、委派需求或任务成败；关系阶段、事件条件等语义由角色模型执行，代码不建关键词表、不伪造确定性状态；装配只做拼接、排序与按声明门控，不改写角色作者原文。
- **BYOK 与固定模型**：ASR 永久 `qwen-audio-3.0-asr-flash-streaming`，TTS/复刻/设计永久 `qwen-audio-3.0-tts-flash`；导入卡中的其他模型字段一律归一化到固定模型，界面与手机端无修改入口。
- **助手永久静音**：只有角色自然语言回复可进 TTS（桌面、手机、Android 壳一致）；通知不携带语音，不绕过 `core/voice_policy.py` 的 `is_tts_eligible` 判定。
- **助手提示词纯净**：助手侧继续只注入一个 Markdown 文件；世界书、HSR 扩展、depth_prompt 等所有角色卡模块只进入角色侧提示词，`assert_single_assistant_markdown` 守卫不得削弱。
- **安全边界**：`command_panels`、导入卡中的任意脚本与活动 HTML 只保存为数据或按声明式组件呈现，永不获得应用执行权限。
- **提交纪律**：只提交本阶段相关文件并写明路径，不用 `git add -A`；未经用户明确要求不提交、推送、打 tag 或发布。

### 0.4 视觉自主权声明

本计划对强视觉 AI 只约定三件事：**功能必须达成什么、必须如实呈现哪些真实状态、必须遵守哪些业务协议与安全边界**。除此之外——审美、视觉语言、信息架构、布局、构图、层次、色彩、材质、字体、图标、动效、过渡、反馈形式、控件形态、交互模式——全部由强视觉 AI 自主决定，本文与逻辑轨不作任何限制。`docs/design/web-prototype/` 原型与 SillyTavern 界面都只是历史参考，不是视觉约束。

## 2. 阶段第一步：契约冻结（强逻辑 AI 先行，双轨共享）

逻辑轨开工第一件事是产出 `docs/plans/V0.3.7-契约冻结.md`，作为双轨唯一共享入口。视觉轨在契约冻结提交前只能做不依赖新命令的准备工作（视觉体系探索、状态清单、组件盘点）。

### 2.1 需要冻结的命令契约（命名可微调，语义与形状必须定稿）

### 2.2 世界书运行时激活契约（核心子集）

语义以 SillyTavern v1.18.0 源码（`public/scripts/world-info.js`）为准，实现以下子集：

- **扫描缓冲**：最近 N 条角色对话消息（user/character，不含工具、思考、系统事件），最新在前；N = 书级 `scan_depth`，未声明时默认 2（对齐 ST 全局默认）。
- **主关键字**：任一命中即通过；支持字面与 `/pattern/flags` 正则关键字（flags 限 `g i m s u y`，非法正则退化为字面匹配并记 warning）；条目 `case_sensitive` 生效，默认不敏感。
- **次关键字**：`selective` 且次关键字非空时启用过滤，四种 selectiveLogic（AND_ANY/NOT_ALL/NOT_ANY/AND_ALL）全实现；卡字段缺省时对齐 ST 默认 AND_ANY。
- **常驻与启用**：`constant` 无条件激活；`enabled=false` 跳过。
- **位置子集**：`before_char`（角色设定前）、`after_char`（角色设定后）、`atDepth`（按条目 depth 与 role 注入对话流，depth 语义 = 距对话末尾第 N 条，对齐 ST splice 行为）。EMTop/EMBottom/ANTop/ANBottom/outlet 位置存而不运行。
- **顺序**：`insertion_order` 大者优先激活；同位置拼接次序对齐 ST（契约冻结时写明精确规则与对照行号）。
- **书级预算**：`token_budget` 生效，超限按激活顺序截断并记录 overflow 条目清单；未声明时按 25% 上下文预算。token 计数方式在契约冻结定案（有真实 tokenizer 用真实，无则写明近似算法与误差边界）。
- **存而不运行清单**（存储保留、兼容报告列出、运行时不执行）：probability/useProbability、递归激活（`recursive_scanning` 存储但不递归）、互斥组（group/groupOverride/groupWeight）、sticky/cooldown/delay、min activations、`@@activate`/`@@dont_activate` 装饰器、automationId、matchPersona*/matchCharacter* 等额外扫描开关、整词匹配全局设置。
- **硬边界**：激活结果只决定条目是否注入角色侧提示词；不反向用于任何意图、委派、成败判定。

### 2.3 装配契约更新

- 落地契约 §9 第 3、4 步：世界书（常驻按 `insertion_order`，关键字条目按激活结果）→ `depth_prompt`（按卡声明 depth 与 role 注入对话流深处）。
- HSR 高级块保持确定顺序（world_architecture → character_architecture → narrative_rules → relationship_system → event_system），渲染从「键: 值」行升级为分节结构化文本；只做排版，不改写原文。
- alternate_greetings、group_only_greetings、creator_notes 的装配/存储边界定稿（备选问候的随机/轮换策略如交给模型则需写明）。
- **确定性触发**：事件池/时间线中声明了明确轮次或明确时间的条目，由运行时按声明在对应回合注入；语义条件（如「关系升温后」）一律交角色模型，代码不解释。
- 装配输出模块列表必须含：模块类型、来源字段、字符区间、世界书命中关键字、预算占用、被截断条目、未展开宏清单。

### 2.4 数据宏契约

- 白名单定稿：`{{char}}`、`{{user}}`、`{{time}}`、`{{date}}`（最终清单以冻结文档为准）。
- 展开时机：装配渲染时对卡字段与世界书命中内容统一展开一次。
- 白名单外宏（变量宏、脚本宏、条件宏）：原样保留不展开，进入装配诊断与兼容报告的「未展开」清单；STScript 永不执行。

### 2.5 Android 壳与通知契约

- 壳形态：Tauri 2 Android 工程（`src-tauri/gen/android`），壳内复用 `desktop/mobile` 同一套前端代码与同一 WS 命令/事件协议、同一配对/token 鉴权；不 fork 第二套业务逻辑。
- 常驻：前台服务保持 WS 连接；服务被杀→壳内如实断连态与重连入口；不伪造后台在线。
- 通知：本地通知（tauri-plugin-notification 或等价方案，契约冻结时以最小 spike 定案）；触发源为现有事件流中的任务完成、委派结果、审批请求；通知只承载状态摘要，点击进入壳后按事件序号对齐增量，通知不是事件来源。
- iOS 不做原生壳，继续 PWA；推送能力缺失作为已知限制写入用户文档。

### 2.6 电源状态契约

- 检测实现放在 Python Sidecar（业务权威层），经 `powercfg` 读取当前电源计划与 AC/DC 睡眠超时；读取失败或非 Windows 如实返回错误/unsupported，不伪造数值。
- 提示触发：远程服务开启 且 睡眠超时低于契约阈值 → `power.status_changed` 扇出风险提示数据；应用只提示与指引，不替用户修改电源设置。
- 轮询/事件节奏、阈值数值在冻结文档定稿。

### 2.7 契约冻结产出物

`docs/plans/V0.3.7-契约冻结.md` 一份：命令/事件完整 payload 形状、世界书激活算法精确语义（含与 ST 源码行号的对照）、装配顺序与诊断字段、数据宏白名单、Android 壳技术定案与理由、电源状态字段、前端 TypeScript 契约同步说明。冻结后双轨各自实现；发现契约缺陷时先改契约文档再改代码，双向同步。

## 3. 强逻辑 AI 轨道任务

### A. PNG 双向兼容

**L1. `card.import_png` 与 peek 升级**。`card.peek_import` 按扩展名/签名分派；PNG 分支走 `read_png_card`（ccv3 优先、chara 回退）；导入时 PNG 字节入受管理资产目录并绑定 `avatar_asset`（`source=png_import`）；返回卡摘要＋`CompatReport`；名称冲突按既有策略；损坏 PNG（签名不符、块截断、base64/JSON 非法、缺 name）如实报 `PngCardError` 可读原因。
验收口径：真实酒馆 PNG 卡导入后名称、设定、问候、世界书、扩展保留且头像可用。

**L2. `card.export_png`**。用卡当前头像经 `write_png_card` 合成 v3 单文件（只写 `ccv3` 块，图像块原始字节复制）；无头像卡如实失败并提示；导出结果展示名称、版本、头像、世界书条目数、问候数、已识别扩展。
验收口径：导出 PNG 在本应用重新导入字段不丢；在真实 SillyTavern 环境可导入（见 §6.3）。

**L3. PNG fixture 与往返测试**。构造最小 PNG fixture（白厄 JSON＋真实头像字节合成）；覆盖 v2(chara)/v3(ccv3) 读取、损坏 PNG 报错、导入→导出→再导入往返（未知扩展与 `extensions.hsr` 不丢）。

### B. 世界书运行时激活

**L4. 激活引擎纯模块**。新建 `character_cards/activation.py`：输入卡（或书）、最近消息序列、预算，输出命中条目、注入位置分组、诊断信息；纯函数、可单测，不依赖 Sidecar/SQLite。实现 §2.2 核心子集全部语义。
验收口径：构造条目集覆盖主/次关键字四逻辑、常驻、禁用、正则、大小写、位置分发、顺序、预算截断；存而不运行字段被忽略且有记录。

**L5. 装配器接入世界书与 depth_prompt**。按 §2.3 更新 `character_prompt_assembler`：世界书命中条目进 before/after 槽位，常驻按 `insertion_order`；`depth_prompt` 与 atDepth 条目需要对话层在消息流倒数第 N 条位置注入（改造角色侧消息构建路径，不动助手侧）。
验收口径：白厄卡对话中，提到世界书关键词时对应条目真实进入角色提示词、不提不进（诊断数据为证）；depth_prompt 出现在声明深度；`assert_single_assistant_markdown` 既有测试零回归。

**L6. 预算截断与诊断**。书级预算生效，截断顺序与 overflow 记录按契约；装配模块列表输出命中关键字、预算占用、截断清单、未展开宏。
验收口径：构造超预算场景，截断行为与诊断记录可核对。

### C. mufy 高级系统装配深化

**L7. 数据宏展开**。装配渲染时对卡字段与世界书命中内容按 §2.4 白名单展开；白名单外宏原样保留并进诊断清单。
验收口径：白厄卡 personality 中 `{{char}}`/`{{user}}` 正确替换；含 setvar 的构造内容不执行、标注未展开。

**L8. 高级块分节渲染与问候/notes 边界**。HSR 五块分节结构化渲染；alternate_greetings、group_only_greetings、creator_notes 按冻结契约装配或保留。
验收口径：白厄卡五个备选问候、扩展字段在导入→装配→导出链路位置可核对，原文不被改写。

**L9. 确定性触发**。事件池/时间线中明确轮次、明确时间的条目由运行时按声明在对应回合注入角色提示词；语义条件条目保持全文可用或按卡声明处理（冻结定案），代码不解释语义。
验收口径：构造「第 N 回合触发」事件，第 N 回合真实出现在装配结果中，其他回合不出现；语义条件不被代码伪造判定。

**L10. 面板与脚本边界锁定**。`command_panels` 仅作数据存储与声明式呈现；构造含脚本/活动 HTML 的导入卡，验证其不获得任何执行路径，兼容报告列入 not_executed。

**L11. Tauri 2 Android 工程**。建立 `gen/android` 壳工程，壳内加载 `desktop/mobile` 同一前端产物；复用同一 WS 协议与配对/token 鉴权；构建链路（含 SDK/NDK 环境要求）写入开发文档。

**L13. 本地通知接线**。任务完成、委派结果、审批请求事件→本地通知（只承载状态摘要）；点击通知进入对应会话并按事件序号对齐增量；通知权限被拒如实提示。
验收口径：后台/锁屏收到审批请求通知，点击后看到真实审批卡；离线期间事件不合成。

## 4. 强视觉 AI 轨道任务

> 本章只定义功能边界、必须呈现的真实状态与协议约束。所有视觉与交互实现决策由强视觉 AI 自主完成（见 0.4）。

### A. 世界书与高级编辑（桌面）

**V1. 世界书条目管理**。条目列表、新建/复制/删除、排序（`insertion_order`）、启用开关、主/次关键字编辑、selective 逻辑选择、常驻开关、位置（before/after/atDepth＋depth/role）、大小写与正则标记、单条目预算影响的呈现。组织、导航、折叠、分步或任何形式由视觉轨定，目标是让用户始终理解「这条设定什么时候会进入角色的脑子」。

**V2. mufy 高级编辑体验**。替换 `AdvancedEditorPanel` 中全部 V0.3.7 占位分区：世界架构、身份外貌、语言方式、行为状态、心理核心、用户关系、关系阶段、时间线、事件池、叙事规则。`command_panels` 以声明式数据呈现，不提供「运行」假象。长文本编辑、未保存退出、保存失败的处理延续 V0.3.5 创作页语义。

**V3. 原始数据查看**。为熟悉酒馆卡的用户提供字段级核对视图（只读 JSON 路径已存在，可扩展），与普通编辑路径清晰隔离，避免误操作。

### B. 导入导出与兼容报告（桌面）

**V4. PNG 导入流程**。选择/拖入 PNG → 解析中 → 导入预览（名称、头像、卡版本、问候数、世界书条目数、已识别扩展、存而不运行字段）→ 冲突处理 → 副本导入 → 成功；损坏 PNG 呈现原始错误摘要。现有导入流程扩展为 JSON/PNG 双格式。

**V5. PNG 导出流程**。导出前预览（头像、元数据完整性、文件名）、保存位置选择、完成与失败反馈；无头像卡导出被真实拒绝时给出设置头像的引导。

**V6. 兼容报告完整 UI**。`CompatReport` 全字段分组呈现：已运行、已保留未运行（含概率/递归/互斥组等清单）、未展开宏、警告、根级字段回退；导入后可在角色详情随时回看，不只存在于导入当下。

### C. Android 壳与通知

**V7. 壳内整体体验**。与 PWA 一致的视觉语言；配对、会话列表、聊天、审批、语音在壳内的完整呈现；原生手势与返回键下的可用性。

**V8. 通知体验**。任务完成、委派结果、审批请求三类通知的文案、优先级与免打扰表达；通知不伪装成对话消息；通知权限被拒、前台服务被杀后的断连表达与恢复入口；常驻条目的呈现（用户能看懂「保持连接中」的含义与关闭方式）。

**V9. 壳与 PWA 的分支管理**。移动端代码继续单仓库单套；壳能力差异（通知、常驻）以能力探测呈现，不维护两套界面。

### D. 电源提示

**V10. 桌面端电源提示**。检测到「远程服务开启＋即将休眠」时的非打扰提示与「保持唤醒」指引（引导用户自行调整系统设置）；状态消失后提示收敛；不代改设置。

**V11. 手机端电源状态**。在线时展示「电脑可能休眠」的真实状态与说明；电脑已休眠/离线沿用既有断连语义，两端表达一致。

### E. 真实状态完整性

**V12. 状态清单覆盖**。本阶段全部新界面覆盖：载入中、空、成功、失败（含原始错误）、进行中、部分成功、不可用（权限/环境/平台不支持）。mock 仅用于开发，验收前全部换真实 Sidecar 状态。

**V13. 双端一致性复查**。桌面、PWA、Android 壳三端对同一失败（PNG 损坏、鉴权失败、断连、休眠、通知权限被拒）的表达语义一致。

## 5. 协作顺序与文件边界

### 5.1 顺序

1. 逻辑轨：产出契约冻结文档（§2）——唯一阻塞项，尽快提交。
2. 视觉轨：契约冻结后即刻并行开工，可先用 mock 后端（`mockDesktopBackend.ts` 同步新命令的模拟实现）。
3. 逻辑轨在契约冻结后紧接着做 Android 壳最小 spike（空壳工程构建＋前台服务＋本地通知跑通），结论回写契约文档。
4. 双轨各自在归属文件内工作；发现契约缺陷→改契约文档→双向同步。
5. 集成期：视觉轨接真实 Sidecar 走查（显式 `--data-dir`），mock 证据不进验收记录。
6. 收尾：共同完成第 6 节真实主路径验收，视觉分支包含逻辑分支全部提交后一次 PR 合入 main。

### 5.2 文件归属

| 归属 | 范围 |
| --- | --- |
| 逻辑轨 | `src/pair_harness/**`、`tests/**`、`desktop/src-tauri/**`（含 `gen/android` 工程与 Rust/Gradle 配置）、`docs/plans/V0.3.7-契约冻结.md`、真机与 SillyTavern 联调记录 |
| 视觉轨 | `desktop/src/ui/**`、`desktop/src/stores/**`、`desktop/src/presenters/**`、`desktop/src/services/**`（mock 层）、`desktop/mobile/src/**`、各 `__tests__`、视觉验收截图 |
| 共享（契约驱动，先改契约再动） | `desktop/src/contracts/`（protocol.ts、actions.ts、view-models.ts）、`src/pair_harness/desktop_backend/commands.py` 命令白名单。约定：命令名与 payload 形状以冻结文档为准，逻辑轨改 Python 侧、视觉轨改 TS 侧，不代改对方文件 |

### 5.3 冲突避免

双轨不编辑对方归属文件；`application_service.py`、`desktopStore.ts`、`mobileStore.ts` 等大文件只由归属轨修改。壳内 UI 复用 mobile 前端，视觉轨改动 `desktop/mobile/src/**` 时不得引入依赖壳专有能力的无条件调用（能力探测先行）。
