## 1. 现有界面审查

当前界面有不错的基础：双栏工作区、消息虚拟化、搭档双色令牌、结构化工具卡片都已存在。以下只列真正影响使用的问题，按严重度排序，每条注明对应文件。

### 1.1 致命：错误直接接管整个窗口

- `error.reported` 事件会把 `status` 置为 `error`，`AppShell.tsx` 随即把整屏换成「启动失败」静态页。WebSocket 1011、Sidecar 一次抖动，用户正在进行的对话就整屏消失，且没有重试入口，只能重启应用。对应任务书问题 9。
- 同理 `disconnected` 状态只给出「请重启应用」。对普通用户这等于宣判死刑。
- 位置：`AppShell.tsx` StatePage 分支、`desktopStore.ts` `error.reported` 分支。

### 1.2 致命：消息没有生命周期状态

- `Message` 协议里没有发送状态字段。用户点发送后，`Composer.tsx` 先清空草稿再 await 提交；提交失败时文字直接丢失，界面上什么都不出现。这解释了「第一条消息有时不显示」。
- 没有「已排队 / 已接收 / 处理中 / 失败」的任何表达。助手忙碌时用户发消息，前端无法告诉用户它去了哪里。
- 位置：`protocol.ts` Message、`Composer.tsx` submit、`desktopStore.ts`。

### 1.3 严重：模式、发送对象、推理等级、审批方式互相牵连

- 模式存在后端会话记录里（`last_mode`），切推理等级走 `project.update_settings` 后快照水合，`hydrateSnapshotState` 用 `last_mode` 覆盖本地 `mode`——这就是「切推理等级后界面回到聊天模式」的机制根源。
- `Composer.tsx` 的目标选择和草稿是本地 `useState`，不看 ViewModel 里的 `composer.target` / `composer.draft`，状态在两处各说各话。
- 位置：`desktopStore.ts` hydrate、`presenters.ts`、`Composer.tsx`。

### 1.4 严重：思考过程是死的

- 思考内容只能从 `message.payload.reasoning` 一次性拿到，渲染成手动折叠块。DeepSeek 流式思考在界面上体现为长时间无任何反馈，然后一次性出现。「逐步出现」无从谈起；展开折叠块还会把下面的消息顶下去，页面跳动。
- 位置：`MessageList.tsx` ReasoningBlock、协议中缺少 reasoning delta 通道。

### 1.5 严重：设置中心和账号体系整体缺失

- 整个应用没有设置页。模型服务商、API Key、语音配置、Codex 登录都没有界面；`ChatColumn` 里「项目设置」菜单项是 disabled 的占位。主题切换藏在聊天栏底部角落。
- 没有账号概念：无登录、无注册、无切换，所有数据单租户存放。
- 位置：`ChatColumn.tsx`、缺失的 settings 模块。

### 1.6 严重：助手消息的空间归属不可靠

- `presenters.ts` 按 `source` 把消息切成两半：角色区拿非 assistant 消息，工作台拿 assistant + tool 消息。后果是用户「直接交给助手」的那条消息（source 是 user）会出现在角色聊天区，助手对它的回复却出现在工作台——一句话被劈成两处，上下文断裂。
- 聊天模式下工作台整栏卸载，助手历史也随之不可见；切回协作模式才重新挂载，滚动位置丢失。
- 位置：`presenters.ts` 的过滤逻辑、`Workspace.tsx` 条件渲染。

### 1.7 中等：语音状态表达太弱

- 语音状态是输入区工具条上一行小字：「聆听中」「语音播放中」「VAD idle」。没有播放队列概念，没有逐条消息的朗读入口，卡顿或合成失败时用户只看到一行红字混在状态文本里，不知道该停哪里、重试什么。
- 「帮我审核」模式下审批文本如果 `tts_eligible` 判断不严就会被朗读；消息类型和可朗读性在前端没有视觉区分依据。
- 位置：`Composer.tsx` voiceStatusText、`protocol.ts` tts_eligible。

### 1.8 中等：审批条会闪烁、会挡路

- `ApprovalBar.tsx` 用本地 `resolvedIds` Set 记录已点过的审批来防重复显示——这是组件级补丁，跨会话、重挂载后失效。审批条固定压在输入区上方，长审批理由会把输入区顶得很高。
- 位置：`ApprovalBar.tsx`。

### 1.9 中等：聊天模式没有表达「项目能力不可用」

- 聊天模式下「交给助手」只是灰色禁用，鼠标悬停才有一句提示。角色被问到项目问题时，界面层面没有任何提示告诉用户「这个角色现在碰不到你的项目」。模式的能力边界只存在于后端提示词里，界面没有承接。
- 位置：`Composer.tsx` segmented、缺聊天模式能力说明组件。

### 1.10 轻微

- 顶栏品牌文字仍是「Pair Harness」，与产品名 HSR Partner Harness 不一致。
- 「取消任务」按钮常驻顶栏右侧，大多数时候是灰色的死按钮，占据视觉重心。
- 首次启动无引导：没有项目时整屏一句「暂无打开的项目 / 等待项目数据」，死胡同。
- 项目轨道里「日常聊天」入口是 disabled 占位，没有说明它将来是什么。

## 2. 设计概念

### 2.1 一句话概念

**「一间房，两盏灯。」**

角色住在房间中央，随时都在；助手在房间一侧的工作台里干活，工作台可以打开也可以合上，但房间本身从不动。

### 2.2 核心体验目标

1. **角色永远在场。** 聊天区是应用里唯一永不卸载、永不换位的面板。切模式、切账号回来、断线重连，用户的对话和滚动位置都在原地。角色陪伴感来自连续性，连续性来自空间稳定。
2. **模式是空间开合，不是页面跳转。** 「协作模式」= 工作台从右侧打开 + 输入区允许直接点名助手。模式开关物理上就是工作台的宽度动画，用户能看懂这个因果关系，也就不会再被「切个设置就跳回聊天」吓到。
3. **每条消息都有下落。** 发送即回显，消息从出生（草稿）到入土（完成/失败/取消）每个阶段都看得见。排队是正式的一等公民，不是 busy 期间的意外。
4. **技术状态翻译成人话。** 连接、引擎、OAuth、VAD 这些词收进「技术详情」抽屉；常态界面只讲「连接中 / 已断开，正在重试 / 需要你处理」。
5. **两种身份，两种质感。** 角色（白厄）是暖的、圆的、有呼吸感的对话；助手（古代机械）是冷的、方的、仪表化的作业。用户扫一眼颜色与形状就知道这句话谁说的、能不能朗读、要不要审批。

### 2.3 概念如何落到布局

```
┌──────────────────────────────────────────────────────────────┐
│ 状态条：连接 · 当前项目 · 模式开关 · 忙碌/取消 · 头像          │
├──┬───────┬─────────────────────────────────┬────────────────┤
│项│ 聊天  │                                 │                │
│目│ 列表  │        角色对话区（常驻）        │   助手工作台   │
│轨│       │                                 │  （可开合）     │
│道│       │                                 │                │
│  ├───────┤ 排队条（有排队时出现）           │                │
│设│       │ 输入区：发给谁 · 草稿 · 语音     │                │
│置│ 头像  │                                 │                │
└──┴───────┴─────────────────────────────────┴────────────────┘
```

双栏结构保留，但性质改变：角色区从「模式 A 的全部」升级为「恒常面板」，工作台从「模式 B 的一半」降级为「可开合侧栏」。聊天模式 = 工作台关闭，协作模式 = 工作台打开。切换只是面板动画，不涉及任何卸载。

## 3. 信息架构

```
应用
├─ 启动层
│   ├─ 启动画面（连接 Sidecar）
│   └─ 账号门（未登录时）
│       ├─ 登录（选账号 + 密码）
│       ├─ 注册（名称 + 密码 + 可选头像）
│       └─ 首次引导（注册成功后三步：建项目 → 配模型 → 完成）
│
├─ 主界面（登录后）
│   ├─ 项目轨道（左 56px）
│   │   ├─ 日常聊天入口（不绑项目的纯角色聊天）
│   │   ├─ 项目徽章列表
│   │   ├─ 新建项目
│   │   └─ 底部：设置入口 · 当前账号头像
│   ├─ 聊天栏（240px，可收起）
│   │   ├─ 项目头（名称、路径健康、项目操作）
│   │   ├─ 新建聊天 / 搜索
│   │   └─ 会话分组列表（运行中 / 今天 / 更早）
│   ├─ 工作区
│   │   ├─ 角色对话区（常驻）
│   │   ├─ 助手工作台（可开合侧栏，协作模式默认开）
│   │   ├─ 审批条（有待审批时浮现在输入区上方）
│   │   ├─ 排队条（有排队消息时浮现）
│   │   └─ 输入区
│   └─ 全局浮层
│       ├─ Toast 队列（右上角，错误与结果通知）
│       ├─ 语音迷你播放条（TTS 播放时浮现在输入区左上）
│       └─ 技术详情抽屉（从状态条连接药丸展开）
│
└─ 设置中心（模态，覆盖主界面，Esc 关闭）
    ├─ 账号（资料、改密码、切换/退出）
    ├─ 编程助手（Codex / DeepSeek 兼容，OAuth 状态）
    ├─ 角色对话模型（服务商、模型、Key、推理等级、测试连接）
    └─ 语音（服务、Key、ASR/TTS 模型、音色、试听、VAD 开关）
```

入口关系：设置从项目轨道底部齿轮进入；账号切换从轨道底部头像或设置中心进入；技术详情从状态条连接药丸进入；所有配置缺失（未配模型、未登录 Codex）都从对应使用场景里就地引导去设置中心对应页，而不是弹无头错误。

## 4. 关键流程

### 4.1 首次启动

启动画面（logo + 「正在唤醒本地服务…」最长 3 秒）→ 无账号则进注册 → 注册成功进三步引导：

1. **创建第一个项目**：选文件夹，默认取文件夹名，可改。
2. **配置角色模型**：服务商下拉（DeepSeek 默认）、填 Key、「测试连接」按钮当场给绿勾或一句人话错误。可跳过，跳过则角色对话暂不可用，输入区有明确引导。
3. **完成页**：一句话介绍两位搭档和两种模式，进主界面，自动打开新聊天。

任何一步可跳过，设置中心随时补配。引导只出现一次（按账号记）。

### 4.2 本地注册与登录

账号门是独立全屏：左侧产品氛围区（搭档插画位），右侧表单卡。登录=账号列表（头像+显示名）点选后输密码；注册=名称、密码、确认密码、可选头像。错误就地红字（「密码不对」「这个名字已被使用」），不弹窗。登录成功记住「上次账号」，下次启动默认选中、只输密码。

### 4.3 切换账号

项目轨道底部头像 → 弹出菜单：当前账号信息、「切换账号」「退出登录」「账号设置」。切换账号回账号门但保留账号列表；应用内所有面板随新账号快照整体水合，因为是全量替换，允许一次明确的加载过渡（200ms 遮罩淡入），不需要逐面板保留。

### 4.4 创建或打开项目

轨道加号 → 系统文件夹选择器 → 确认卡（文件夹路径、项目名默认文件夹名、审批方式默认「每次问我」）→ 创建后自动选中并新建聊天。打开已有项目=点徽章；文件夹不可用时徽章带黄色角标，点开先见修复横幅再决定继续只读还是重选路径（沿用现有 `repairProjectPath` 交互，位置不变）。

### 4.5 普通聊天

聊天模式（工作台关）。输入、回车、消息立刻以「发送中」样式出现在角色区（半透明+小时钟图标），后端确认后转常态，失败则气泡转红边+「重试」链接。角色流式回复带光标。草稿在切聊天、切模式、断线时都保留（按会话存）。

### 4.6 切换到协作模式

状态条模式开关或快捷键（Ctrl+J）→ 工作台从右侧以 250ms 滑出到上次宽度，输入区「交给助手」段亮起。角色区宽度自适应收窄但消息流不重新排版跳动（宽度动画期间文本不做重排闪烁，采用 overflow 裁剪过渡）。切回聊天=工作台滑入收起，其内部滚动与未完成内容在内存中保留。

### 4.7 角色委派助手

协作模式下用户让角色处理项目任务 → 角色区出现角色的简短回应（「我请机枢看看这个报错」），同时工作台出现一张**委派卡**：写明「来自白厄的委派」+ 任务摘要 + 状态。助手执行期间工具卡依次追加，完成后委派卡变完成态，角色区再出现一句简短总结。委派卡是角色区与工作台之间的视觉桥梁，让用户看清任务从谁手里到了谁手里。

### 4.8 直接交给助手

输入区切到「交给助手」（或 @助手 前缀）→ 发送后这条用户消息**只出现在工作台**，作为任务的发起卡；角色区不出现。助手回复与工具记录也都在工作台。角色区可以在原地出现一条极轻的系统痕（「你直接派了一个任务给机枢 · 查看」），点击滚动定位到工作台对应卡片——可关闭的提示，不是消息。

### 4.9 忙碌期间提前发送和排队

任何时刻输入区都可输入可发送。忙碌时发送的消息进入排队条（输入区上方的横向胶囊条）：

```
┌ 排队 2 条 ────────────────────────────────────┐
│ ① 给白厄：「帮我想想这个名字」 · 等待当前回复结束   │
│ ② 给机枢：「跑一下测试」 · 等待上一个任务结束      │
│         [编辑] [撤回] [立即插入]                  │
└───────────────────────────────────────────────┘
```

每条胶囊显示：发给谁（头像色点）、内容摘要、排在第几、在等什么结束、hover 出操作（编辑=拉回输入区、撤回=移除、立即插入=请求中断当前后优先处理，需确认）。队列开始处理时胶囊滑出，对应消息进入对话区。

### 4.10 查看思考与流式回复

助手/角色开始回复前，先出现**思考缎带**：一条细高的内联块，左侧脉动圆点 + 「正在思考…」，思考增量以打字机方式进入缎带内部（内部滚动，缎带高度封顶 120px，不顶动下方内容）。思考结束缎带自动收成一行摘要「思考了 8 秒 · 展开」，正式回复从其下方开始流式出现。用户全程可选：点摘要重新展开阅读。回复区高度变化只向下生长，配合「回到底部」悬浮按钮，已读区域绝不位移。

### 4.11 修改模型配置

设置中心 → 角色对话模型：改任何字段后「保存并测试」亮起；保存即生效（下一条消息起），不需要重启。测试连接中按钮转圈，结果就地显示：绿勾「连接正常（延迟 x ms）」或红字一句人话（「Key 无效，请检查后重试」+ 技术详情链接）。

### 4.12 Codex OAuth 登录

设置中心 → 编程助手 → 选「使用 Codex」→ 「通过浏览器登录」：按钮 → 系统浏览器打开授权页，设置页原地显示「等待浏览器授权…」与倒计时 → 授权完成事件回来，卡片变绿「已登录 xxx · 退出/重新授权」。API 登录=填 Key + 保存并验证。OAuth 过期时下次用助手先在 Toast 提示一次，工作台出现一张授权卡，不反复弹。

### 4.13 配置语音和试听

设置中心 → 语音：服务地址与 Key（高级里收 WebSocket 地址）、ASR/TTS 模型下拉、角色音色与助手音色各带「试听」按钮（合成一句固定台词「你好，我是白厄」/「系统就绪」）。试听按钮三态：试听中（转圈+可停止）、成功（自动播完恢复）、失败（红字+详情）。页顶总开关「语音功能」，关闭后输入区语音按钮整体隐藏而非禁用。VAD 一行：开关 + 状态药丸（就绪/运行中/不可用），不暴露模型文件概念。

### 4.14 连接失败后的恢复

连接状态机四种面貌：

- **正常**：状态条绿色小点「已连接」，平时几乎隐形。
- **抖动重连**：状态条变「连接中…」黄点自动重试，界面其余部分照常可用（已加载内容都在），输入可用，消息进入排队。
- **重连失败超过 30 秒**：黄点变红「连接已断开」，Toast 出现一次「与本地服务失去连接，正在重试。查看技术详情」，不刷屏；此后每次重试静默进行。
- **手动**：点连接药丸展开技术详情抽屉（最近错误、Sidecar 状态、日志路径、「立即重连」「重启本地服务」按钮）。

唯一还允许整屏错误的情况：启动期 Sidecar 根本无法拉起。

## 5. 状态设计

统一原则：状态附着在它发生的对象上（消息、任务、连接、语音），不上浮到整屏。下表是界面表达规范。

| 状态 | 视觉表达 | 位置 | 用户可做的 |
|---|---|---|---|
| 草稿 | 输入框常态；切走再回来文字还在；未发送的草稿在会话列表行尾显示铅笔小标 | 输入区 + 会话列表 | 继续写、丢弃 |
| 正在发送 | 气泡 60% 透明 + 右上小时钟图标，即刻回显 | 对应对话区 | 等待（不可编辑） |
| 已排队 | 气泡转为排队条胶囊：色点（发给谁）+ 序号 + 等待说明 | 输入区上方排队条 | 编辑、撤回、立即插入 |
| 正在思考 | 思考缎带脉动点 + 打字机增量，高度封顶内部滚动 | 回复气泡上方 | 收起缎带 |
| 正在回复 | 文字逐段出现 + 行尾闪烁光标；面板头部状态签「正在回复…」 | 对话区 | 停止生成（长按取消键/ESC） |
| 正在调用工具 | 工具卡蓝条旋转图标「运行中」，工作台头部「任务运行中」+ 取消按钮 | 工作台 | 取消任务 |
| 等待审批 | 审批条浮现在输入区上方，琥珀色左边条；对应工具卡变「等待批准」暂停态 | 输入区上方 | 允许 / 本会话允许 / 否决 / 查看详情 |
| 已取消 | 气泡或任务卡灰化 + 删除线摘要「已取消」，保留原内容可回看 | 原地 | 重新发送（用户消息） |
| 已失败 | 红左边条 + 一句人话原因 + 「重试」按钮；技术细节收进展开区 | 原地 | 重试、复制详情 |
| 正在恢复连接 | 状态条黄点「连接中…」，排队条提示「恢复后自动发出」 | 状态条 | 等、查看技术详情 |
| 语音合成中 | 迷你播放条：声波动画 + 「正在合成语音…」，可取消 | 输入区左上浮层 | 取消合成 |
| 语音播放中 | 迷你播放条：当前朗读者头像色点 + 摘要 + 进度 + 停止/跳下一条 | 输入区左上浮层 | 停止、跳过 |
| 语音失败 | 迷你播放条变红一句人话（「语音服务没响应」）+ 重试；文字阅读全程不受遮挡 | 浮层内 | 重试、关闭浮层 |

补充规则：

- 同一时刻只有一个「全局进行态」在状态条（连接 > 任务 > 语音），其余状态各归各位。
- 所有可恢复状态给明确的下一步动作，不允许出现「坏了但没有按钮」。
- 状态变化用 150–250ms 的颜色/透明度过渡，不用弹跳、不用闪烁。
- 「正在组织语言…」是「正在回复」的前置子状态：角色流式 JSON 解析出第一个自然语言字段之前的缓冲期使用，呼吸圆点 + 细字，不占用气泡正文；首个干净文字到达即无缝替换。原始 JSON 任何时刻不上屏。

- **状态条**（高 44px）：左=连接药丸；中左=当前项目名+路径健康点；正中=模式开关（聊天/协作，物理上就是工作台开合）；中右=任务状态（平时隐形，忙碌时出现「任务运行中 · 取消」，闲时取消按钮不存在，不常驻死按钮）；右=账号头像菜单。
- **角色区**：占满工作台关闭时的全部宽度；打开时自适应。头部常驻：白厄色点+名字+状态签（正在回复/聆听中/空闲）。
- **工作台**：右侧面板，默认占 42%，拖柄范围 30–60%（沿用现有交互与键盘操作）。头部：机枢色点+名字+「任务运行中/空闲」+收起按钮。内容三类卡：委派卡、助手消息卡、工具卡。底部有自己的空状态（「把任务交给机枢，执行记录会出现在这里」）。
- **聊天模式**：工作台宽度 0（卸载内容保留在 store，DOM 移出但状态保留），输入区「交给助手」禁用并带说明；角色区头部加一条常驻轻提示签「纯聊天 · 白厄暂时看不到你的项目」，首次进入聊天模式时展开一句说明，之后折叠成签。

### 6.3 消息组件规范

| 气泡 | 形状/色彩 | 特别元素 |

### 6.4 设置中心

模态全屏遮罩（背景主界面压暗），面板宽 880px 居中，左侧 200px 栏目导航（账号/编程助手/角色模型/语音），右侧内容卡。所有表单：标签用大白话（「服务商」「接口地址」配灰色小字说明「就是 API Base URL，一般不用改」），技术参数统一收进每页底部的「高级设置」折叠区。危险操作（改密码、退出 OAuth）需要二次确认。

### 6.5 空状态与加载

- 无项目：主区插画位 + 「从选一个文件夹开始」+ 大按钮，附一句「项目就是你想让机枢帮忙干活的文件夹」。
- 无聊天：角色区居中「和白厄聊聊吧」，输入区聚焦。
- 工作台空：「把任务交给机枢，执行记录会出现在这里」+ 「试试：让它介绍一下这个项目」快捷按钮（点一下自动以「交给助手」发出预设任务，新用户立刻看到工作台活起来）。
- 加载：骨架屏只用于会话切换的消息区（3 条灰条），其余场景用状态签，不用骨架。

## 7. 视觉系统

### 7.1 色彩

沿用现有令牌骨架（`tokens.css` 已有双主题与搭档色组，测试锁定白厄色值），在其上补三层：

- **层一·基底**：深色 `#0E1116` 窗底 / 浅色 `#F4F6F9`，面板逐级提亮。长时间使用默认深色，对比度控制在 WCAG AA。
- **层二·身份**：角色蓝（`--pair-character` 系）与助手青铜金（`--pair-assistant` 系）。身份的表达规则：**色点、左边条、状态签用身份色；气泡底色保持低饱和**，大段文字永远是中性底，避免整屏蓝金刺眼。浅色主题下身份色整体降饱和一档（现有令牌已有雏形，扩展成套）。
- **层三·语义**：成功绿 / 警告琥珀 / 危险红 / 运行蓝（现有），新增「排队紫灰」一档，让排队在色觉上和「失败」「运行」都分开。

### 7.2 字体与排版

- UI：`Microsoft YaHei UI / Segoe UI`，字阶沿用 16/15/14/12 四档。
- 代码与工具明细：`Cascadia Mono`。
- 正文行高 1.5（22/15），消息气泡内边距 10×14px；气泡最大宽度 72%，工作台内卡片通栏。

### 7.3 形状语言

- 角色侧：大圆角（12–16px）、柔和、无锐利边条——「人」。
- 助手侧：小圆角（4–8px）、左边条、mono 字体元素——「机械」。
- 系统与状态：胶囊（999px）——「界面自身在说话」。
- 这套形状语言本身就是身份标识，色盲用户也能靠形状分辨。

### 7.4 动效

- 面板开合 250ms `ease-out`；状态变色 150ms；菜单 200ms。全部沿用现有令牌，不新增弹跳类动效。
- 新增三条：思考缎带脉动（1.2s 呼吸）、排队胶囊滑入滑出（200ms 位移）、流式光标闪烁（1s）。流式文本本身不做逐字动画，只做追加。

### 7.5 主题

深浅双主题全量覆盖新组件；主题切换即时、不闪屏（CSS 变量过渡 150ms）。主题偏好按账号记忆（并入账号数据，接口清单见 §8）。

### 8.1 账号

| 项目 | 类型 | 界面影响 |
|---|---|---|
| `account.list` → 账号列表（id、显示名、头像、是否上次登录） | 新增命令 | 账号门账号卡列表 |
| `account.register / account.login / account.logout` | 新增命令 | 账号门表单；登录成功进主界面 |

### 8.2 消息生命周期

| 项目 | 类型 | 界面影响 |
|---|---|---|
| `chat.submit` 改为「先回执后处理」：后端**同步落库**后立即返回 `message_id` 与初始状态，并随即推 `message.created`；前端用真实 id 即时回显，毫秒级空窗可本地先画、回执到达按 id 对账。不靠纯前端乐观气泡 | 调整 | 发送即回显的基础 |

| 事件 `message.status_changed` | 新增事件 | 气泡状态图标与排队条更新 |
| 队列数据：每条排队消息的目标（角色/助手）、序号、阻塞它的任务描述 | 新增快照+事件 | 排队条渲染 |

| 草稿持久化（按会话存草稿文本） | 新增（或前端本地存） | 切换会话/模式/断线后草稿还在 |

### 8.3 流式与思考

| 项目 | 类型 | 界面影响 |
|---|---|---|
| `message.delta` 已有，`channel` 区分正文 | 已有 | 流式正文 |
| DeepSeek 角色输出是**流式 JSON**：后端做增量解析，只把解析出的自然语言字段（speech 等）作为干净 delta 推送，原始 JSON 永远不直接上屏；解析失败的兜底是把原始内容收进「技术详情」而不是灌进气泡 | 新增（后端解析层） | 角色气泡只出现干净文字；首字段缓冲期间显示「正在组织语言…」呼吸态 |
| 流式 JSON 中的结构化委派字段解析后以结构化数据随事件下发 | 新增 | 委派卡的数据来源，与文字流同源 |
| 思考增量通道：`message.delta` 的 `channel: "reasoning"` + 思考开始/结束事件 | 新增 | 思考缎带打字机与自动折叠「思考了 x 秒」 |
| 消息目标字段：用户消息标记发给角色还是助手 | 新增字段 | 「交给助手」的消息只进工作台，不进角色区（修 1.6） |
| 委派关系字段：助手任务卡携带 `delegated_by: character` 与摘要 | 新增字段 | 委派卡 |

### 8.4 模式与独立状态

| 项目 | 类型 | 界面影响 |
|---|---|---|
| 模式由后端按会话持久化，但必须是**独立字段**：`conversation.set_mode` 单独读写，任何设置类命令（推理等级、审批方式）不得在快照中回推覆盖模式；快照水合尊重后端持久值，前端切换走显式命令 | 调整 | 修「切推理等级跳回聊天」；模式连续性有后端权威，界面开合体验不变 |
| 推理等级、审批方式、发送对象、模式四者各自的读写命令互不影响 | 调整确认 | 设置类操作不引起布局变化 |

### 8.5 配置

| 项目 | 类型 | 界面影响 |
|---|---|---|
| `config.get / config.set`：角色模型（服务商、模型、BaseURL、Key、推理等级）、语音（服务、Key、ASR/TTS 模型、双音色、开关）、编程助手选择 | 新增命令 | 设置中心三页 |

### 8.6 语音

| 项目 | 类型 | 界面影响 |
|---|---|---|
| 语音状态机扩展：`idle / synthesizing / playing / failed`，携带当前朗读的 message_id 与队列长度 | 调整 | 迷你播放条三态与「跳下一条」 |

### 8.7 连接

## 9. 前端实施计划

按阶段推进，每阶段独立可验收。范围只列 React / 样式 / 测试，协议与 Python 由强逻辑 AI 按 §8 对接。

### 阶段 0 · 状态基座（最高优先，直接修线上痛点）

- `desktopStore`：消息状态字段、排队列表、错误分级、连接状态机的事件处理。
- 新组件：`QueueStrip`（排队条）、`ConnectionPill`（状态条药丸）、`ToastStack`、`TechDetailsDrawer`。
- 改造：`Composer` 发送即回显 + 失败重试；`AppShell` 只有 `fatal` 才整屏；`TopBar` 取消按钮改为忙碌才出现。
- 测试：发送回显/失败重试、排队条增删、错误分级渲染、断线重连状态流转的 store 单测与组件测试。

### 阶段 1 · 空间重构

- `Workspace` 改为「常驻角色区 + 可开合工作台」，模式=开合状态；工作台内容离屏保留。
- `presenters`：按消息目标字段（而非仅 source）分配消息归属；用户直发助手的消息归工作台。
- 新组件：`DelegationCard`（委派卡）、角色区「纯聊天」能力签。

## 10. 验收场景

每个场景对应任务书里的真实问题，验收标准是「用户能否看懂正在发生什么、操作是否连续」。

1. **首条消息回显**：新建聊天发第一条消息 → 气泡立刻出现（发送中样式）→ 转常态。断网模拟后端异常 → 气泡红边 + 重试，文字不丢。
2. **审核模式语音**：「帮我审核」下触发审批 → 审批条出现；语音只朗读角色自然语言回复，审批文本与工具记录静音；消息类型在气泡形态上可区分。
3. **状态独立**：协作模式下切推理等级 → 工作台保持打开、模式不变、对话不动。
4. **聊天模式能力边界**：聊天模式问项目问题 → 角色自然说明 + 角色区能力签可见 + 输入区有「切换到协作模式」引导；全程无隐藏的助手调用。
5. **项目感知**：协作模式问「这个项目是什么」→ 角色委派，工作台出现委派卡与助手分析，角色不再反问路径。
6. **语音播放**：连续两条回复 → 播放条显示队列与当前条；卡顿/失败 → 播放条红态一句人话 + 重试；全程文字阅读不被遮挡，可随时停止/跳下一条。
7. **助手消息归属**：「交给助手」发任务 → 该消息与助手回复、工具记录全部在工作台；角色区无污染，只有可关的轻痕提示。
8. **模式无缝切换**：聊天中切协作再切回 → 草稿、滚动位置、已完成内容原样保留，工作台开合是动画不是刷新。
9. **连接错误**：制造 WebSocket 1011 → 状态条黄点「连接中…」+ 一次 Toast，不刷屏不整屏；技术详情抽屉能看到原始错误；恢复后排队消息自动发出。
10. **思考流式**：DeepSeek 推理 → 思考缎带逐字出现且页面不跳 → 自动折叠为「思考了 x 秒」→ 正文开始流式。
11. **排队可见**：助手忙碌时连发两条 → 排队条显示发给谁、排第几、等什么结束；可编辑、撤回、立即插入；开始处理时平滑转入对话区。
12. **能力可见性**：新用户从注册到发出第一个任务，能在界面上找到并理解：任务状态与取消、排队、流式、工具调用、审批、错误恢复、历史会话、项目绑定、模型选择、语音配置——无需询问，无需看日志。
