# V0.3.3 收尾：验收结论、缺陷清单与 V0.3.4 归置

> 日期：2026-08-22
> 验收形态：真机（小米手机浏览器）+ 局域网 + 真实引擎（Reasonix ACP + DashScope BYOK）
> 分支：`v0.3.3-visual-ai`（已包含 `v0.3.3-logic-ai` 全部提交，两轨无分叉，无需额外合并动作）
> 详细过程见 `docs/v0.3.3-logic-ai-acceptance.md` 与 `docs/v0.3.3-visual-ai-acceptance.md` 第 4 节。

## 1. 验收结论

计划 V0.3.3"集成与验收"中不依赖打包形态的项全部通过：局域网配对与鉴权全套、真实引擎委派主链路（多段思考流式 → 工具卡 → 审批挂起 → 批准 → 真实落盘 `hello.txt` → 角色总结 → 自动标题）、断网/杀后台/重启重连与水合、桌面远程页撤销、内置角色对话、草稿持久化、固定模型、思考段/工具卡/气泡走查、语音边界佐证（全程助手无 TTS 请求，仅角色消息进入 TTS）。

唯一无法在手机端执行的验收项是"手机发送角色消息并收到真实回复"——手机端没有角色消息入口，见缺陷 3。

## 2. 缺陷清单（全部归 V0.3.4 修复）

| # | 现象 | 根因 | 修复方案 |
| --- | --- | --- | --- |
| 1 | 语音设置页保留"第四面镜声音复刻"生成项，点击被服务端拒绝（`助手侧说话方已禁用语音: fourth_mirror`），"一键 4 项"永远无法完成 | `fourth_mirror` 在配对 `march7_fourth_mirror` 中是助手侧；服务端已按 V0.3.3 冻结边界拒绝助手 TTS，但前端 `VOICE_SPEAKER_DEFINITIONS` 仍把第四面镜留在专属音色生成列表，UI 与边界不一致 | 从专属音色生成列表移除第四面镜（助手侧一律不出现在声音复刻中），文案改"3 次/3 项"；或按当前配对动态只列角色侧说话方 |
| 2 | 手机上角色的委派指令显示为"你：查看项目目录…"，桌面端则正确显示"来自 白厄 的委派"卡片 | 协议消息带 `origin`（`user` / `character_delegation` / `system`），桌面端 `presenters.ts` 按 `origin=character_delegation && delegation_id` 渲染委派卡；手机端 ChatPage 未实现该识别，按 source 渲染成用户气泡 | 手机端消息渲染增加 `origin=character_delegation` 分支，渲染为"来自 <角色名> 的委派"卡片（复用桌面委派卡语义，状态与 delegation_id 对齐） |
| 3 | 手机端无角色消息输入入口（只有委派输入 `target=assistant`），计划验收项"手机发送角色消息"无法执行 | 手机端 P0 交付范围只含委派输入，与计划集成验收标准存在偏差 | V0.3.4 在手机聊天页增加普通消息输入（`target=character`），与委派输入明确区分 |
| 4 | 手机端无模式切换控件：会话处于聊天模式时委派必被服务端拒绝（`assistant_not_allowed_in_chat_mode`），手机 UI 无前置提示、无法自行切换 | 手机端只读 `conversation.last_mode`，不提供 `conversation.set_mode` 入口 | V0.3.4 手机端增加模式切换控件，或对聊天模式下的委派输入给出前置禁用与说明 |
| 5 | 手动 Ctrl+C 关闭 `--serve` sidecar 时，aiohttp WS 连接清理抛未处理异常（`CancelledError` 级联 `InvalidStateError`，traceback 刷屏） | `asyncio.run` 被 KeyboardInterrupt 打断时，aiohttp 在途 WS handler 任务在 shutdown 阶段二次抛错，无统一捕获 | `main()` 捕获 KeyboardInterrupt 后走与 `app.shutdown` 相同的有序停机路径；修复后 Ctrl+C 退出码 0、无 traceback |
| 6 | 远程设备页二维码在桌面应用内不可用（Codex Review 复核确认）：`window.location.hostname` 在 Tauri WebView 是 127.0.0.1 或内部主机名，且端口固定 1421（vite dev 场景），扫码后访问的是不可达地址 | 二维码 payload 未从 Sidecar/Rust 获取真实局域网地址与伺服端口（8765） | 由 Rust 侧提供真实 LAN IP（或 Sidecar 上报监听地址），二维码按 `http://<LAN-IP>:8765/?ws=…&code=…` 生成 |
| 7 | **撤销 token 后事件流继续下发（安全，已核实）**：`PairingService.revoke` 只标记 token 失效，`ws_server` 无按设备关闭已建立连接的路径；已鉴权连接在撤销后继续收到聊天消息、工具结果与审批事件 | `_RemoteConnection` 完成一次鉴权后永久订阅 `EventFanout`，扇出时不重新鉴权；真机验收第 17 项的"手机立即断开"实为手机端下一条命令被拒后自行断开，静默在线的设备仍收事件 | 撤销时由服务端立即关闭（或退订）对应该 token 的现有连接；`_RemoteConnection` 记录 token 供撤销定位；补"撤销后静默连接不再收到事件"的回归测试 |
| 8 | 手机端角色思考增量拼进正文气泡（Codex Review 复核确认）：角色思考流以 `kind=character.speech + channel=reasoning` 下发，手机端 `useChatTimeline` 只识别 `kind=assistant.reasoning` | 手机端缺少桌面端 `desktopStore.ts` 已有的 `source=character && channel=reasoning` 分支 | 手机端 timeline 与桌面同步按 `channel=reasoning` 识别思考增量，渲染进折叠思考段而非正文 |

## 3. 验收会当场修复（已随本分支提交，不属 V0.3.4）

1. **Tauri→sidecar `--serve` 接线**（V0.3.3 计划条 11 的集成缺口）：`main.rs` 固定传 `--serve 8765` 并注入 `PAIR_HARNESS_PWA_DIR`（dev 取 `desktop/mobile/dist`，打包找 resource `mobile-dist`）。
2. **serve 端口冲突降级**：端口被占等 `OSError` 时如实上报 `error.reported(serve_start_failed, fatal=false)` 并继续桌面 stdin 路径，桌面应用不因端口占用整体挂掉（`__main__.py` + 集成测试）。
3. **auth_failed「重新配对」入口失效**：两处入口只 `navigate` 未清凭据，被路由守卫弹回；改为先 `disconnect()` 清凭据再跳转，测试补齐断言。

## 4. 预期行为澄清（非缺陷）

- **协作模式下助手回复后角色搭话**：v0.3.2 起角色—助手协作链路的设计行为——任务/消息处理完成后，角色以自己的口吻回应或总结执行结果（验收通过项"角色总结到达"即此机制）。桌面与手机行为一致。
- **手机 PWA 经 PC 8765 端口伺服时二维码（指向 1421）不可扫**：二维码 payload 按手机 vite dev 场景生成；静态伺服形态手输配对码即可。V0.3.4 打包接入时按真实伺服地址生成二维码。

## 5. PR 审查备注（非阻塞）

- **CodeQL 警告「Binding a socket to all interfaces」**：`tests/integration/test_serve_mode.py` 端口冲突测试绑 `0.0.0.0` 是刻意的（与 `WSServerMode` 同地址族才能在 Windows 下测出冲突，代码内已注释）。V0.3.4 加行内抑制注释 `# codeql[py/bind-socket-all-network-interfaces]`。
- **Dependency Review ⚠️ 25 包 OpenSSF Scorecard 问题**：0 漏洞、0 许可证问题，属供应链健壮性观察项，V0.3.4 顺带评估是否升级。
