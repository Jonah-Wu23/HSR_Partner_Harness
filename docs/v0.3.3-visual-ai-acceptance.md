## 1. 代码实现（对照强视觉计划）

- 骨架：mobile PWA 基座（wsClient 五态连接机、mobileStore 事件一致性、hash 路由、配对守卫）、desktop 骨架三笔（角色库/设置/契约接线）。
- W1 角色库：`desktop/src/ui/character-library/`。统计行（共 N 个 · 筛选出 M 个 · 草稿/归档计数）、来源与音色双筛选、搜索、使用中置顶条（继续编辑入口）、卡片工具条（查看/编辑/复制/导出/归档/删除，hover 出现）、删除确认弹窗（说明字段/世界书/头像移除与音色解绑）、导入失败卡（解析中断如实呈现）、内置卡「内置 · 只读」徽标。内置角色不提供编辑入口。
- W2 创作页：`desktop/src/ui/character-create/`。面包屑、快速创建（基础信息/人格设定，字数计数与必填标注）、保存状态机（已保存时间戳）、高级编辑分区导航：基础组四项标 V0.3.5、世界组与人设组、扩展组标 V0.3.7，占位说明「当前阶段不提供伪造的保存表单」。
- W3 设置：`SettingsCenter.tsx` 五栏目（账号/编程助手/角色对话模型/语音/远程设备）。语音页：`VOICE_SPEAKER_DEFINITIONS` 仅留白厄/流萤/三月七/第四面镜四位，萨姆与神秘的古代机械已从说话方与界面移除，助手语音开关整块删除；「生成 4 个专属音色」；自定义角色参考音频与音色创建如实注明「将于 V0.3.5 开放」，接口保留只读不删除。远程设备页：六位配对码、二维码（payload `http://<局域网地址>:1421/?ws=ws://<局域网地址>:8765/ws&code=<配对码>`）、300 秒倒计时、过期态、设备列表（已授权/已撤销徽标、撤销二次确认）、局域网地址如实注明以 Sidecar 实际监听为准。
- W4 手机基座：配对页（扫码回退手动输入、设备名预填）、聊天列表页（项目分组、会话条目）、ConnectionBanner 五态视觉分级（connected 隐藏；connecting/reconnecting 警示色；unreachable/auth_failed/disconnected 醒目红 + 重试/重新配对入口）。
- W5 手机聊天：消息来源分色气泡（你/助手/角色/系统）、工具卡多态（运行中/已完成/失败可展开）、思考段折叠流式、委派输入（`chat.submit` target=assistant）、审批只读卡（详情完整、无批准/拒绝按钮、标注「请在电脑端处理」）。

## 3. 真实联调（真实 sidecar `--demo --serve 8791`，独立数据目录）

### 3.1 接线核对（`.tmp/verify_card_wiring.py`，此前批次）

- `card.*` CRUD 与 `remote.*`（issue_code/pair/revoke/list）全通；角色草稿与配对状态重启后持久化。
- 事故记录：早期脚本漏传 `--data-dir` 污染用户真实库，已清理（残留草稿删除、两台走查设备 revoked，revoked 留痕属设计行为）。此后所有走查脚本强制显式 `--data-dir`。

### 3.2 手机端全链路（Playwright iPhone 15 模拟 + 真实 sidecar）

配对 → 列表 → 聊天 → 切协作模式 → 委派「创建 hello.txt」→ 审批挂起 → 模拟电脑端批准 → 完成。期间事件序号连续无缺口。

### 3.3 走查钓出的真实缺陷与修复（全部已提交并回归）

| 症状 | 根因 | 提交 |
| --- | --- | --- |
| 手机配对成功后不跳转 | App 守卫 render 期读 localStorage 不刷新 | 15f396e |
| 审批卡永不出现 | mobileStore 按嵌套解析 approval.requested，真实 payload 为平铺 | a93fa6e |
| 刷新落在聊天页报「WebSocket 未连接」 | openConversation 与 WS 握手竞态，且不重试 | 24f09a5 |
| 有挂起审批时 app.bootstrap 永远无响应 | broker.snapshot() 直出 PendingOperation 对象，响应编码失败（服务端潜伏 bug，桌面端因审批不落库从未触发，手机重连场景暴露） | d5e37e9 |
| 断线时聊天页出现两条相同 banner | App 层与 ChatPage 重复挂载 ConnectionBanner | ca99473 |
| 设置页点「远程设备」整页卡死 | AppShell 内联回调 + 面板 effect 依赖不稳定引用，「拉取 → setState → 重渲染 → 重拉」死循环 | 3a316af |

另：委派工具卡停在「运行中」经查证为审批挂起的**真实状态**（协议实验 `.tmp/repro_event_stream.py` 证明扇出完好、序号零缺口），非缺陷；批准后卡片翻转「已完成」、系统消息「审批结果：允许」、角色总结到达、会话自动标题生成，均已验证。
