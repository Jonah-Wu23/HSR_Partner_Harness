## 1. 全局硬性准则（所有成员）

1. **Let It Fail**：真实失败直接抛出/落库，不得捕获异常后返回空列表、None、合成成功提示。测试必须让错误直接失败。
2. **Let It Go**：不新增任何关键词/正则式的意图判定逻辑。消息来源字段（`MessageSource`）、命令方法名是唯一判定依据。
3. 白名单外文件一律只读。发现冲突停手报告，不自行发挥。
4. 完成定义统一包含：新测试全过 + `.\.venv\Scripts\python.exe -m pytest -q` 全量无回归（本地基线 522 passed / 5 skipped；`test_desktop_sidecar_loop` 的命名管道集成测试在完整权限环境跑）。
5. 报告格式（严格 JSON）：`{"changed_files": [...], "created_files": [...], "test_commands": [...], "test_summary": "...", "deviations": [...], "open_questions": [...]}`

## 2. 角色卡持久化契约（成员 A）

### 2.1 数据库迁移 9

`sqlite_store.py`：`SCHEMA_VERSION` 8→9，`MIGRATIONS` 追加元组 9；`storage/schema.sql` 同步追加相同表（新库直建 + 旧库迁移两条路径必须结构一致）。

```sql
CREATE TABLE IF NOT EXISTS character_cards (
    card_id TEXT PRIMARY KEY,
    state TEXT NOT NULL,
    name TEXT NOT NULL,
    source TEXT NOT NULL,
    card_json TEXT NOT NULL,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS character_assets (
    asset_id TEXT PRIMARY KEY,
    card_id TEXT NOT NULL,
    kind TEXT NOT NULL,
    mime_type TEXT NOT NULL,
    file_path TEXT NOT NULL,
    source_ref TEXT NOT NULL DEFAULT '',
    created_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_character_assets_card ON character_assets(card_id);
```

- `state` 存 `CharacterCardState` 值；`source` 取 `builtin | user_created | imported_json | imported_png`；
- `card_json` 存 `codec.dump_card_v3(card)` 的完整文本（权威位置：酒馆标准字段 + `extensions.hsr`，见 `docs/character-card/角色卡数据契约.md`）；
- `character_voice_profiles` 不建独立表：音色绑定存于 `card_json` 的 `hsr.voice_profile`（接入清单 §1 的决定）；
- 旧库升级不得触碰已有表数据；迁移失败如实抛出。

class CharacterCardRepository:

## 3. 远程传输与事件扇出契约（成员 C）

### 3.1 端口布局

`--serve <port>` 在同一端口开 aiohttp 服务器：`GET /` 及静态路径伺服 PWA 产物（`static_root`，构造注入；`None` 时静态路由返回 404，如实报错不合成页面）；`GET /ws` 升级 WebSocket。依赖 `aiohttp>=3.9` 加入 `pyproject.toml` 主 dependencies（当前 venv 已装 3.14.3）。

### 3.2 EventFanout（`event_fanout.py`）

```python
RemoteEventWriter = Callable[[dict], None]   # 同步写一条已编码 envelope

class EventFanout:
    def __init__(self, stdout: JsonlWriter) -> None: ...
    def subscribe(self, writer: RemoteEventWriter) -> "Subscription": ...
    def publish(self, envelope: dict) -> None: ...
```

- `publish` 先写 stdout（`JsonlWriter`，唯一权威）；再逐个写已订阅连接；
- 单个订阅者写失败：清理该订阅者并 `logger.warning`，不影响 stdout 与其他订阅者；
- stdout 断开语义完全由 `JsonlWriter` 现有 BrokenPipeError 路径承担，fanout 不拦截不改写；
- 订阅与发布线程安全（asyncio 单线程模型下用普通同步实现即可，不做额外锁）。

### 3.3 WSServerMode（`ws_server.py`）

```python
ReplySink = Callable[[dict], None]   # 把 response/protocol_error 写回发起连接

class WSServerMode:
    def __init__(self, *, dispatch: Callable[[str, ReplySink | None], None],
                 authenticator: RemoteAuthenticator, fanout: EventFanout,
                 static_root: Path | None, port: int) -> None: ...
    async def start(self) -> None: ...
    async def stop(self) -> None: ...
```

- WS 文本帧等同 JSONL 行。`dispatch(line, reply_sink)` 由主控批 3 接到 `SidecarRouter.dispatch`（扩展签名，向后兼容）；
- 解析失败的帧走 `protocol_error` 路径：构造与 `router.handle_line` 相同的 protocol_error envelope，写回该连接（能识别 id 时带上）；
- **鉴权门在 dispatch 之前**：每条请求先提取 `payload["auth"]["token"]`（无则 `None`），调 `authenticator.authorize(token, method)`；拒绝时写回 `response_error(request_id, "unauthorized", reason)` 并记审计，不进 dispatch；
- 连接建立/断开：断开时从 fanout 退订并清理；连接异常不向上传播影响服务器；
- 事件下行：连接完成鉴权后自动订阅 fanout（收到与 stdout 相同 envelope，含 `sequence`）。

### 3.4 鉴权接口（C 定义 Protocol，D 实现）

```python
@dataclass(frozen=True)
class AuthDecision:
    allowed: bool
    reason: str = ""         # 拒绝原因，进审计日志
    device_name: str = ""    # 允许时的设备名

class RemoteAuthenticator(Protocol):
    def authorize(self, token: str | None, method: str) -> AuthDecision: ...

UNAUTHENTICATED_METHODS: frozenset[str] = frozenset({"remote.pair"})
```

`UNAUTHENTICATED_METHODS` 以模块常量放在 `ws_server.py`（批 3 由主控同步进 `commands.py` 注册表）。C 的测试用桩实现此 Protocol。

### 3.5 序号与重连语义

事件 envelope 的 `sequence` 由现有 `EventEmitter` 分配（单一源头，不动）。重连对齐：客户端重新 WS 连接→鉴权→调用现有 `app.bootstrap` 拉当前状态快照→继续消费 `sequence` 更大的新事件。P0 不做事件回放缓冲，不合成离线期间未发生的事件。

### 3.6 C 的测试要求

`tests/unit/test_event_fanout.py`：扇出顺序与 stdout 优先、单订阅者故障隔离、stdout BrokenPipe 语义保持。
`tests/unit/test_ws_server.py`（aiohttp 测试工具 + 本机 localhost）：未鉴权命令被拒且拿到 `unauthorized` 错误、`remote.pair` 放行到 dispatch、鉴权后命令进 dispatch 且 response 写回发起连接、事件扇出到已鉴权连接、静态路径穿越拒绝、`static_root=None` 时 404。
冒烟（写入报告）：本机起服务，两个 WS 客户端收到同一序号事件流，杀掉一个客户端后另一个继续收事件。

## 4. 配对与鉴权契约（成员 D）

### 4.1 PairingService（`pairing.py`，纯逻辑，不碰网络与共享文件）

```python
class PairingError(RuntimeError):
    def __init__(self, message: str, *, code: str) -> None: ...   # code: expired | used | invalid

class DeviceInfo(TypedDict):
    device_name: str; issued_at: str; last_used_at: str; revoked: bool

class PairingService:   # 实现 RemoteAuthenticator
    def __init__(self, *, ttl_seconds: int = 300,
                 clock: Callable[[], float] | None = None) -> None: ...
    def issue_code(self) -> str: ...          # 6位数字，secrets 随机，一次性，TTL 300s
    def claim(self, code: str, *, device_name: str) -> str: ...
        # 成功返回 token（secrets.token_urlsafe(32)）并作废该码
        # 过期→PairingError(code="expired")；已用→"used"；错误→"invalid"
    def authorize(self, token: str | None, method: str) -> AuthDecision: ...
        # token 有效且未撤销→allowed；更新 last_used_at
        # None/无效/已撤销→拒绝，reason 区分 missing_token / invalid_token / revoked_token
        # method 未在白名单（UNAUTHENTICATED_METHODS）且 token 无效→拒绝
    def revoke(self, token: str) -> bool: ...
    def list_devices(self) -> list[DeviceInfo]: ...
    def export_state(self) -> dict: ...       # JSON 可序列化；供主控批 3 持久化到 app_state
    def load_state(self, state: dict) -> None: ...
    def audit_entries(self) -> list[dict]: ...  # 连接、鉴权失败、命令来源；不含消息正文与密钥
```

### 4.2 安全规则

- 随机数一律 `secrets`，禁止 `random`；token 比较用 `hmac.compare_digest`；
- 恒定时间比较；token 只存哈希或原文内存态（export_state 不输出明文 API Key——本模块根本不接触 API Key）；
- 鉴权失败是真实失败：不降级放行、不静默重试；
- 审计条目字段：`{"at": iso时间, "event": connect|auth_failed|command, "detail": 设备名/方法名/原因}`。

### 4.3 D 的测试要求

`tests/unit/test_pairing.py`：配对码一次性（同码二次 claim 抛 used）、过期（注入假 clock）、错误码、token 撤销后 authorize 立即拒绝、`list_devices` 元数据正确、export/load_state 往返、审计含鉴权失败记录且无密钥字段、`remote.pair` 无 token 可通过 authorize、其余方法无 token 拒绝。

## 5. 助手 TTS 边界冻结（成员 B）

### 5.1 行为表（V0.3.3 起冻结）

| 消息（source × kind） | tts_eligible | 行为 |
| --- | --- | --- |
| CHARACTER × CHARACTER_SPEECH | true | TTS 全路径保持现状，一字不改 |
| ASSISTANT × ASSISTANT_NATURAL_LANGUAGE | **false** | 自动朗读、手动重播、预览、排队、重试全部不可进入 TTS 请求 |
| ASSISTANT × 工具/思考/系统等全部其他 kind | false | 同上（本就静音，保持） |
| 其他 source/kind 组合 | false | 静音 |

### 5.2 代码落点

1. `core/voice_policy.py` `is_tts_eligible`：删除 `(ASSISTANT, ASSISTANT_NATURAL_LANGUAGE)` 条目；`extract_speech_segments` 若仅剩助手路径使用则连同其正则与测试一并删除（先全局检索调用点确认，角色路径若也用则保留并说明）。
2. `core/voice_runtime.py`：入队路径（现 ~426-476 行）对助手消息短路；助手 NL 的分段朗读逻辑成为死代码则删除。
3. `desktop_backend/application_service.py` **仅限语音 handler**（`_voice_tts_play/_voice_tts_skip/_voice_preview/_voice_provision` 及注册表行）：对助手消息调用返回 `ServiceError`（code 如 `assistant_tts_disabled`），真实错误非静默成功；`voice.provision` 对助手说话方（依据 `config/pairs/*.yaml` 的 `assistant:` 侧 speaker，即 sam、ancient_machine）拒绝创建入口。v0.3.2 已生成的助手音色 ID 在 provider_configs 中保留为无效旧数据，不删除不迁移。
4. `config/voices.py`：manifest 结构不动（含助手说话方素材，属无效旧数据保留）；如存在"助手音色开关"类配置项，在 `settings.py` 语音段删除或停用。
5. `desktop_backend/voice_factory.py`：若助手音色装配路径因上述改动成为死代码，删除装配分支。
6. 前端界面的助手语音入口移除属强视觉 AI 轨道，B 不碰 `desktop/`。

### 5.3 判定依据

消息来源字段是唯一依据。禁止任何以消息文本内容判断"这是不是助手消息"的逻辑。固定模型断言（`target_model == qwen-audio-3.0-tts-flash`）保持。

### 5.4 B 的测试要求

新增/改造测试：助手消息全 kind 断言不产生 TTS 请求（含自动朗读、手动 play、preview 三入口）；助手 speaker 的 provision 被拒；角色消息 TTS 路径既有断言全部保持通过（回归不改断言）；`tts_eligible` 单元断言新表。
