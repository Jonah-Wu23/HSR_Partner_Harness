## 1. 核心原则

1. **唯一权威位置**：同一数据只保存在一处。酒馆标准字段存标准位置；酒馆未覆盖的内容存 `data.extensions.hsr`；两者不得互相复制。
2. **无损往返**：导入 → 导出 → 再导入后，标准字段、问候、世界书、第三方扩展、`data` 未知字段和根级未知字段不丢失。
3. **不做语义猜测**：世界书关键词只用于角色卡内容激活；代码不得据此判断用户是否要求委派、是否需要工具、角色情绪或任务成败。
4. **不执行导入内容**：导入卡中的脚本与 HTML 只作为数据保留，兼容报告标记「已保留但未运行」。
5. **失败保持失败**：JSON 非法、缺必填字段、PNG 元数据损坏时直接抛错（`CardImportError` / `PngCardError`），调用方置为 `invalid` 并保留原始错误，不生成空卡。

## 3. `data.extensions` 的划分

| 内容 | 权威位置 | 处理 |
|---|---|---|
| 第三方/SillyTavern 扩展（`talkativeness`、`fav`、`world`、`depth_prompt`、`regex_scripts` 等） | `data.extensions.{key}` | 原样保留、原样写回；`depth_prompt` 提供类型化只读视图 `card.depth_prompt`，不另存副本 |
| HSR 扩展 | `data.extensions.hsr` | 见 §5 |
| `data` 下未知字段 | `data.{key}` | 原样保留在 `card.data_extras`，导出时写回 `data` |

## 8. PNG 载体约定

- 读取：`tEXt` 块关键字 `ccv3`（v3，优先）或 `chara`（v2/旧 v3回退），值为 base64(UTF-8 JSON)。
- 写入：仅写 `ccv3`；已有 `chara`/`ccv3` 块替换不叠加；新块插入 IHDR 之后，图像块（IDAT 等）按原始字节复制。
- 损坏（签名不符、块截断、base64/JSON 非法、缺 `name`）→ `PngCardError`，保留可读原因。

## 9. 运行时装配顺序（契约冻结，本期不接入对话链路）

角色回合的提示词按以下确定顺序装配，每一步可诊断、可按卡片声明启用/禁用：

1. 标准角色设定模块（description / personality / scenario）
2. `system_prompt`（卡内系统提示）
3. 世界书（常驻条目按 `insertion_order`；关键词条目仅由**角色卡内容激活**——关键词命中只决定该条目是否注入，不用于任何用户意图或任务成败判断）
4. `depth_prompt`（按声明 depth 与 role 注入）
5. `post_history_instructions`
6. HSR 高级扩展（world_architecture → character_architecture → narrative_rules）
7. 关系与事件模块（relationship_system、event_system；阶段与条件由角色模型执行，代码不伪造确定性状态）
8. 头像资产（纯展示，不进入提示词）
9. 角色音色状态（`voice_profile`；仅角色自然语言可进 TTS，助手与工具事件永久静音——本契约只提供状态数据）

硬边界：角色卡只影响角色对话、角色记忆与角色 TTS；不能赋予工具执行权限，不能覆盖助手职责；助手提示词永远只注入其单一 Markdown 文件，角色卡任何模块不得混入。

## 10. 兼容报告（`CompatReport`）

导入返回 `ImportResult(card, report)`，报告字段：`applied`（已装配模块）、`preserved`（原样保留的第三方扩展与根级字段路径）、`not_executed`（已保留但永不执行，如 `command_panels`）、`normalized_from_root`（从根级回退的字段）、`warnings`、`errors`。导出结果展示（名称、格式版本、头像、世界书条目数、问候数、已识别扩展）由调用方从模型 + 报告生成，不用合成成功提示掩盖失败。
