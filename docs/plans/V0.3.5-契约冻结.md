## 2. 角色卡命令契约

### 2.1 `card.peek_import_json`（导入预览，不落库）

请求：`{"path": "<绝对路径.json>"}`。响应：

```json
{
  "ok": true,
  "preview": {
    "name": "白厄",
    "spec_version": "3.0",
    "avatar_available": false,
    "greeting_count": 6,
    "world_book_entries": 20,
    "tags": ["..."],
    "report": {
      "applied": ["..."], "preserved": ["..."], "not_executed": ["..."],
      "normalized_from_root": ["..."], "warnings": ["..."], "errors": ["..."]
    }
  }
}
```

`report` 字段与 `character_cards/codec.py` 的 `CompatReport` 一一对应。文件不存在、JSON 非法、缺 `name` → 错误响应（`code`：`card_import_failed`，message 含原始错误摘要），不得返回空预览。

### 2.2 `card.import_json`

请求：`{"path": "...", "as_duplicate": false}`。行为：经 `load_card_json` 解析后落库，`state="imported"`、`source="tavern_import"`。**同名不视为冲突**（库内 `name` 无唯一约束），`as_duplicate=true` 时名称追加「（副本）」。响应：`{"card_id", "name", "state": "imported", "report": {...}}`（report 同 2.1）。

### 2.3 `card.export_json`

请求：`{"card_id": "...", "path": "<导出绝对路径>", "save_avatar": true}`。行为：`dump_card_v3` 写文件；`save_avatar=true` 且卡有头像资产时，头像字节另存为 `<去扩展名路径>.avatar.<ext>`。内置卡（`builtin:` 前缀）只读，导出前须先复制（`card.duplicate` 拒绝内置——内置卡导出直接报 `card_read_only`）。响应：`{"exported": true, "path": "...", "avatar_saved": false}`。写失败 → 原始错误。

### 2.4 `card.publish`

请求：`{"card_id": "..."}`。行为：`draft → saved`。校验（缺一报 `card_publish_invalid`，message 指明缺什么）：`name` 非空、`first_mes` 非空。非 draft 状态调用为幂等成功（返回当前 state）。响应：`{"card_id", "state": "saved"}`。

### 2.5 `card.set_avatar` / `card.remove_avatar`

`card.set_avatar` 请求：`{"card_id": "...", "path": "<本地图片绝对路径>"}`。行为：读文件字节 → 复制入受管理资产目录（`<data_dir>/character_assets/<asset_id>.<ext>`）→ `character_assets` 表落库（kind=`avatar`）→ 更新卡 `hsr.avatar_asset`（`source="user_upload"`、`source_ref=原文件名`、`mime_type` 按文件探测，探测不出报错）。已有关联资产先删再写。仅支持 png/jpeg/webp，其他格式报 `card_avatar_unsupported`；文件 >5MB 报 `card_avatar_too_large`。响应：`{"card_id", "asset_id", "mime_type"}`。

`card.remove_avatar` 请求：`{"card_id": "..."}`。行为：解绑 `hsr.avatar_asset`、删资产文件与表记录。响应：`{"card_id", "removed": true}`。

`card.get` 响应新增 `avatar` 字段：卡有头像时 `{"mime_type": "...", "data_base64": "..."}`，否则 `null`（头像随 get 整体下发，避免独立命令；`card.list` 摘要继续只有 `has_avatar` 布尔）。`card.delete` 时同步清理该卡全部资产（头像与参考音频）。

### 2.6 资产服务（内部）

新模块 `character_cards/assets.py`：`CharacterAssetService(store, root: Path)`。`store_asset(card_id, data: bytes, kind, mime_type, source, source_ref) -> asset_id`、`get_asset(asset_id) -> (bytes, mime_type)`、`list_assets_for_card(card_id)`、`delete_assets_for_card(card_id)`。`app_paths.AppPaths` 增加 `character_assets` 属性（`data_dir/character_assets`），`ensure()` 一并创建。真实 IO 失败直接抛，不吞。注：v9 `character_assets` 表无 `source` 列，`source` 溯源枚举不进资产表，其权威位置是卡 JSON（`hsr.avatar_asset.source` / `hsr.voice_profile`），由调用方写卡时落库。

## 3. 角色卡音色契约

状态机沿用 `CharacterVoiceState`：`voice_unconfigured → voice_creating → voice_ready | voice_failed`。

### 3.1 `voice.card_bind_reference`

请求：`{"card_id": "...", "path": "<本地音频绝对路径>"}`。行为：读文件 → 探测时长/大小（wav 可本地解析；mp3/m4A 探测失败时如实报错，不猜测）→ 校验格式 ∈ {wav, mp3, m4a}、≤10MB、≤60s（违反报 `voice_reference_invalid`，message 指明原因）→ 资产化（kind=`reference_audio`）→ 写 `hsr.voice_profile.reference_audio_asset`。不改变 `state`（旧 ready 音色在重新创建前仍有效）。响应：`{"card_id", "asset_id", "duration_seconds", "size_bytes", "mime_type"}`。

### 3.2 `voice.card_create`

请求：`{"card_id": "...", "mode": "clone" | "design", "prefix": "可选", "voice_prompt": "design 模式必填", "preview_text": "design 模式可选试听文本"}`。

> `preview_text` 依据 `docs/character-card/千问参考音频能力验证记录.md` 探针 4 的真实错误回执（"provide url, or provide both voice_prompt and preview_text"）：声音设计必须同时提供 `voice_prompt` 与 `preview_text`；缺省使用固定默认文本（≥15 字符）。V0.3.5 真实联调补充结论：`preview_text` 少于 15 字符会被服务端以 `InvalidParameter: preview_text should not be shorter than 15 characters` 拒绝，前端传入过短文本时由服务端原始错误如实回显，不做本地猜测改写。

行为：
- 只用当前账号已存 `voice.api_key`/`voice.base_url`，缺失报 `voice_not_configured`。
- 每卡互斥：同卡 `voice_creating` 中重复提交报 `voice_card_provision_in_progress`。
- `clone`：要求已绑定参考音频（3.1），否则报 `voice_reference_missing`；参考音频本地文件转 data URI 提交 `QwenVoiceCustomizationClient.create_cloned_voice`（V0.3.3 已验证路径）。
- `design`：`voice_prompt` 非空文本提交 `create_designed_voice`。
- `prefix` 可选，规则 ≤10 位小写字母/数字；缺省由卡名生成（小写化、去非字母数字、截 10；为空回退 `card`）。
- 成功：写 `hsr.voice_profile`（`state=voice_ready`、`voice_id`、`creation_mode`、`prefix`、`updated_at`），立即持久化。失败：`state=voice_failed`、`last_error=脱敏后原始错误`（复用 `_redact_voice_error`），**旧 voice_id 保留不清空**。
- 每次状态迁移都发事件 `voice.card_provision_changed`：

```json
{"card_id": "...", "state": "voice_creating|voice_ready|voice_failed", "voice_id": "...|null", "error": "...|null"}
```

响应（命令返回最终态）：`{"card_id", "state": "voice_ready", "voice_id": "..."}` 或错误。助手侧无此流程（卡音色只属于角色卡，天然无助手侧）。

### 3.3 `voice.card_unbind` / `voice.card_preview`

`voice.card_unbind` 请求 `{"card_id"}`：`voice_id=""`、`state=voice_unconfigured`、`creation_mode=""`；**不在用户供应商账号侧删除旧 ID**；参考音频资产保留。响应 `{"card_id", "state": "voice_unconfigured"}`。

`voice.card_preview` 请求 `{"card_id", "text": "可选试听文本"}`：要求 `state=voice_ready`，经 PC 本地扬声器播放（与 `voice.preview` 同 `enqueue_text` 路径），缺卡音色报 `voice_card_not_ready`。响应 `{"voice": <voice 快照>}`。

### 3.4 对话内卡音色生效

`_effective_voice_pair(pair_id)` 扩展为 `(pair_id, conversation_id)`：对话绑定卡且 `hsr.voice_profile.state == "voice_ready"` 且 `voice_id` 非空 → 有效 pair 的 `character.voice_id` 覆盖为卡音色；其余路径不变（账号级 → .env 作者 → 不可用）。助手侧永不覆盖、永不可用。

## 4. 对话绑定角色卡（迁移 v10 与装配）

### 4.1 存储

迁移 v10：`ALTER TABLE conversations ADD COLUMN character_card_id TEXT NULL`。`conversation.create` 增可选参数 `character_card_id`：显式传入则用之；未传且存在 active 自定义卡（`state ∈ {saved, imported}`、未归档；draft 不生效）则快照 active；否则 NULL（内置角色）。`conversation.open` 响应的 conversation 对象新增 `character_card_id` 字段（可 null）。

### 4.2 装配与降级

- 新模块 `core/character_prompt_assembler.py`：`assemble_character_prompt(card: CharacterCard) -> AssembledPrompt`，`AssembledPrompt = {system_text: str, modules: list[AssemblyModule], first_mes: str}`。装配顺序按 `docs/character-card/角色卡数据契约.md` §9（本阶段实现标准字段＋`hsr` 已有内容块的确定性拼接；世界书关键字激活与 depth_prompt 运行归 V0.3.7，装配器留模块位不实现）。只拼接、排序、加小节标题，**不改写作者原文**。
- `OpenAICompatibleDialogueModel` 构造参数新增 `character_prompt_resolver: Callable[[str], AssembledPrompt | None] | None`（入参 `conversation_id`）。`_system_prompt`：resolver 命中 → `f"{assembled.system_text}\n\n{assistant_brief}\n\n{_OUTPUT_FORMAT_INSTRUCTION}"`；未命中 → 现状（内置 YAML）。**助手 brief 与输出协议指令永远来自内置 pair YAML，卡内容不进入。**
- resolver 由 `DesktopApplicationService` 提供：查 conversation → `character_card_id` → 卡存在（含已归档，归档不毁卡）→ 装配缓存；卡已被删除 → 返回 None（回退内置）。
- 降级提示：`conversation.open` 时绑定卡已被删除 → 发一条 `system` 系统消息事件「该聊天绑定的角色卡已被删除，本轮起回退内置角色」，不静默换人。归档不触发降级。
- 首句：绑定卡的对话创建后，若卡 `first_mes` 非空，服务端插入一条 `source=character` 开场消息（走既有消息落库与事件路径）。内置对话行为不变（现状无开场白机制，保持）。

### 4.3 生命周期语义（测试锁定）

1. 切换 active 卡只影响**之后创建**的对话；已开对话的 `character_card_id` 快照不变。
2. 删除正在被对话绑定的卡：对话下次打开按 4.2 降级提示。
3. 重启后 `character_card_id` 持久化恢复，角色身份一致。

## 5. 手机语音契约

固定模型不变（ASR `qwen-audio-3.0-asr-flash-streaming`、TTS `qwen-audio-3.0-tts-flash`）。传输定案：**JSON 文本帧 + base64**（不引入二进制帧；保持现有 JSONL 单一协议形态。16kHz/16bit/mono PCM 上行有效负载 ≈ 32KB/s，base64 后 ≈ 43KB/s，局域网与 Tailscale 均可承受）。

### 5.1 上行（手机 → PC）

| 命令 | 参数 | 行为 |
| --- | --- | --- |
| `voice.mobile_ptt_start` | `{conversation_id}` | 校验会话归属；创建转写会话 `session_id`，启动 `QwenStreamingRecognizer`（16kHz）。响应 `{session_id}` |
| `voice.mobile_audio_chunk` | `{session_id, seq, data}` | `data` = base64(PCM s16le 16kHz mono)。`seq` 从 0 严格递增，跳号报 `voice_audio_seq_gap`。客户端按 100–400ms 分片。送识别器 |
| `voice.mobile_ptt_stop` | `{session_id}` | 结束识别，取 final 转写文本，以 `target=character` 走既有 `_chat_submit` 路径进入该 conversation。响应 `{session_id, transcript, conversation_id}`；转写为空报 `voice_transcript_empty`（如实，不提交空消息） |

事件 `voice.mobile_transcript`（remote-only）：`{conversation_id, session_id, text, is_final}`——partial 与 final 都发，手机端展示转写中状态。识别器本身产出错误（ASR 服务失败）时 `voice.mobile_ptt_stop` 报 `voice_asr_failed`（message 含底层错误，不吞、不回退空文本）；转写成功但文本为空才报 `voice_transcript_empty`。

说话结束判定在**手机端**（按住松开，或手机本地静音检测自动调 `ptt_stop`）；PC 侧不做手机音频 VAD。`target` 固定 `character`（角色对话）；委派仍走文本输入。

### 5.2 下行（PC → 手机）

角色自然语言回复且 `is_tts_eligible=true` 且**当前存在已鉴权远程连接**时，PC 用 `QwenSpeechSynthesizer`（卡音色或账号音色，按 3.4 解析）流式合成，事件下发：

- `voice.mobile_tts_chunk`（remote-only）：`{conversation_id, message_id, seq, mime: "audio/pcm;rate=24000", data}`（base64 PCM s16le 24kHz mono，与桌面 `AudioPlayer` 同规格）。
- `voice.mobile_tts_end`（remote-only）：`{conversation_id, message_id}`。
- `voice.mobile_tts_failed`（remote-only，Codex 复核后增补）：`{conversation_id, message_id, error}`——供应商合成失败时如实下发（含脱敏原始错误），手机端退出播放状态并展示诊断；不合成失败回执。
- 命令 `voice.mobile_tts_stop` `{message_id}`：手机端中断播放时通知 PC 停止合成与下发。

助手、工具、思考、系统消息**零音频下发**（沿用 `is_tts_eligible`，不新增判定）。无远程连接在线时不合成（不空耗额度）。`voice.mobile_*` 三事件经 `EventFanout` 新增的 remote-only 通道下发：**只写远程连接，不写 stdout**（避免大流量进桌面协议）。

### 5.3 错误与鉴权

全部命令需 token（不在 `UNAUTHENTICATED_METHODS`）；未鉴权上行音频被拒并留审计。音频会话绑定发起连接，连接断开 → 未完成会话自动取消（识别器关闭，无残留）。音频通道任何异常不得影响文本命令、审批与桌面 stdout 路径。

## 6. 审批仲裁与命令来源

- `SidecarRouter.dispatch` 增加 `origin` 参数（默认 `"desktop"`；WS 路径传 `"remote"`），`DesktopCommand` 增加 `origin` 字段。`approval.resolve` 由此获得来源，**服务端注入，不信任前端参数**。
- `ApprovalBroker`：已决审批保留短时结果记录（approval_id → `{decision, resolved_by, resolved_at}`）。第二次 `resolve` 同一审批：不再报笼统的 `approval_not_found`，改报 `approval_already_resolved`，message 带「已由 <desktop/mobile> <approve/deny>」，响应体含 `{decision, resolved_by}`。`approval.resolved` 事件增加 `resolved_by: "desktop"|"remote"` 与 `decision` 字段，双端据此收敛。
- 归属不变：手机应答经 WS → `SidecarRouter` → 同一 `handle_command`，任务归属与 conversation 一致。
