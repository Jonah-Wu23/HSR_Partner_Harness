| 项 | 内容 |
| --- | --- |
| 版本 | v0.2（与当前实现基线一致） |

---

## 1. 背景与目标

HSR Partner Harness 是一个「角色扮演 × 编程助手」双人桌面应用：用户与
一个有性格的虚拟角色对话，角色可以在协作模式下把真实项目任务委派给
本地编程助手执行。产品解决的核心问题：

1. **让编程助手有人格**：不是冰冷的工具面板，而是通过角色扮演获得
   自然的对话入口与情感表达；
2. **让对话能做事**：角色不是只会聊天——协作模式下它能委派助手读取、
   修改、运行项目，任务过程与结果回流到对话；
3. **让自动化可控**：助手的一切工具操作都经过沙箱与审批闸门，用户
   始终掌握决定权。

产品目标：单机本地优先、开箱即用（内置模型与引擎二进制）、隐私可控
（账号/密钥/引擎数据本地隔离）。

## 2. 目标用户与使用场景

| 用户 | 场景 |
| --- | --- |
| 角色扮演 + 编程双栖用户 | 让角色帮忙"看一下项目""改个东西"，同时享受角色对话体验 |
| 需要审批控制的开发者 | 用"帮我审核"模式让 AI 审查工具操作，高风险操作仍需人工确认 |
| 对本地隐私敏感的开发者 | 账号、密钥、会话数据全部本地存储，可离线使用演示模式 |

典型旅程：注册本地账号 → 引导选择模型服务商并完成连接测试 → 进入
默认项目 → 与角色对话 → 切换到协作模式让角色/自己把任务交给编程助手 →
工具操作经审批执行 → 结果由角色汇报 → 语音可朗读回复。

## 3. 产品定位与设计原则

- **对话驱动**：一切能力从对话进入，不是功能面板堆砌；
- **双空间呈现**：角色区（对话与情感）与工作台（工具与执行）并列，
  角色"说人话"，助手"干实事"；
- **本地业务权威**：状态、审批、存储由本地服务决定，界面只是呈现；
- **可控的自动化**：安全（审批/沙箱）优先于效率，自动化不绕过用户。

## 4. 功能需求（大功能）

### F1 角色扮演对话

用户与角色进行自由对话，角色由角色卡（人设、表达风格）驱动。

- 流式回复：思考链（reasoning）与正文（speech）双通道流式上屏；
- 角色卡 + 搭档配置驱动语气与人格；每轮注入近期对话上下文保持记忆；
- 项目运行上下文注入（模式、项目名、时间时区），角色能感知"当前
  在哪、能不能动项目"；
- 聊天模式（默认）：角色不能读取或操作项目，明确告知用户并建议
  切换协作模式。

**验收要点**：对话流畅流式；角色在聊天模式下不产生任何项目操作。

### F2 协作模式与编程助手委派

协作模式下，角色可以把任务委派给本地编程助手（产品内称"古代机器"），
用户也可以直接给助手发指令。

- 角色委派：角色台词携带结构化委派（任务/修改），经确认后由助手执行；
- 直发助手：用户直接向助手下达任务，与委派走同一执行管线；
- 任务执行：助手真实读写项目文件、运行命令、调用工具，过程以
  工具卡片实时呈现；
- 执行结果回流：任务结束后角色依据真实回执（成功/失败/取消）汇报，
  禁止虚构成功；
- 运行中指令：任务执行中用户可追加新指令（立即插入优先于排队）；
- 队列：任务忙碌时新指令先入队，当前回合完成后自动派发，失败可重试；
- 取消任务：一键取消，角色如实汇报取消状态。

**验收要点**：委派 → 执行 → 角色汇报闭环完整；工具调用过程可见；
忙碌时提交不丢失、自动排队。

### F3 双编程引擎

编程助手可选择两种本地引擎，共享同一套事件/审批协议：

- **Codex 引擎**（默认）：OpenAI Codex app-server，支持浏览器 OAuth
  与 API Key 登录；
- **DeepSeek 引擎**：本地 DeepSeek-Reasonix 的 `reasonix acp` 子进程，
  复用角色对话的服务商与密钥；
- **演示模式**：无外部凭据的脚本流程，用于离线体验界面与审批模式。

**验收要点**：切换引擎后下一个任务立即生效；两种引擎的工具/审批
事件呈现一致。

### F4 审批与安全

助手的一切工具操作经过安全闸门，三种审批模式：

| 模式 | 行为 |
| --- | --- |
| 请求批准（默认） | 每次工具操作都弹审批请求，由用户裁决 |
| 帮我审核 | 低风险操作由审查智能体自动放行；高风险（删除、破坏性 git、网络、装依赖、系统级命令等）仍需用户批准 |
| 完全允许 | 不弹审批，直接执行（写操作仍受沙箱约束） |

- 项目沙箱：写操作越界项目目录直接否决；
- 审批请求以卡片形式呈现，允许/否决/本对话内允许；
- 审查智能体的裁决理由与调整建议留痕在对话时间线。

**验收要点**：三种模式行为差异明确；越界写操作在任何模式下都被拦。

### F5 会话与项目管理

- 项目绑定本地文件夹；项目内可建多个聊天会话；
- 新会话标题自动生成（首条消息后异步完成，不打断对话）；
- 会话按项目组织，侧栏随时切换，历史消息完整恢复；
- 项目设置：审批模式、推理档位（低/中/高/极高/最高）可随时调整。

**验收要点**：新聊天自动得名；重启后项目/会话/消息完整恢复。

### F6 多账号与本地账户体系

- 本地注册/登录多个账号，密码本地派生存储；
- 账号是完整隔离边界：项目、聊天、配置、密钥、引擎数据目录互不
  串扰；
- 首次引导：注册后引导选择模型服务商（DeepSeek / OpenAI 兼容 API /
  OpenAI OAuth）、填写并测试连接、选择项目文件夹；
- 账号偏好（主题、语音开关）独立保存。

**验收要点**：切换账号后数据与配置完全隔离；引导完成后进入主界面。

### F7 语音交互

- **语音输入**：自动静音检测（VAD）聆听 + 按住说话（PTT）两种方式，
  语音转写为消息发送（可选目标：角色或助手）；
- **语音朗读**：角色与助手的自然语言回复自动进入朗读队列；
  命令输出、工具记录等非自然语言保持静音；
- 逐条重播、跳过、停止；试听角色/助手音色。

**验收要点**：说话→转写→发送闭环；回复朗读自动触发且不朗读工具记录。

### F8 桌面形态与稳定性

- 单个 exe + 内置资源（Python 服务、引擎二进制）分发包；
- 本地服务崩溃自动退避重连（1s→2s→…→15s），重连后界面自动恢复
  最新状态；
- 所有数据本地持久化，无云同步依赖；
- 断线期间保留已加载内容，不整屏接管。

**验收要点**：杀进程后界面自动恢复；重启后状态完整。

### F9 消息与工作台双空间

- **角色区**：用户发给角色、角色台词、系统状态；
- **工作台**：发给助手的指令、助手回复、工具卡片、委派卡、审批栏；
- 思考链折叠展示；工具卡片实时更新状态（运行中/成功/失败/否决）；
- 委派卡把角色区的委派与工作台的执行结果连接起来；
- 错误分级提示：可恢复错误入通知队列，致命错误整屏提示。

**验收要点**：双空间消息归属正确；工具过程实时可见；回复中的"三个点"
状态永不卡死（失败即终结）。

### F10 设置与连接管理

- 设置中心四页：账号 / 模型 / 编程助手 / 语音；
- 模型页：服务商、Base URL、模型、API Key（掩码回显）与连接测试；
- 编程助手页：引擎选择（Codex / DeepSeek），Codex 登录态管理；
- 语音页：开关与状态查看；
- 配置保存后立即生效（下一个任务/回合使用新配置）。

**验收要点**：连接测试给出明确成功/失败原因；保存后不重启即生效。

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 消息提交即时回显；流式增量上屏无明显卡顿；长任务运行期间聊天不被阻塞 |
| 安全 | 密钥本地明文存储但界面只回显掩码；API Key 不进日志；沙箱兜底拦截越界写操作 |
| 可靠 | 后台回合失败可见可重试，不留悬空状态；事件序号契约保证断线重连后状态一致 |
| 兼容 | Windows 桌面；DeepSeek 与 OpenAI 兼容端点均可作为对话服务商 |
| 可维护 | 引擎/服务商/角色/审批规则均可配置化扩展；分层清晰（壳/视图/业务） |

## 6. 优先级与版本边界

- **P0（核心闭环）**：F1 角色对话、F2 委派与执行、F4 审批、F5 项目会话、
  F8 桌面形态；
- **P1（体验增强）**：F3 双引擎、F6 多账号、F7 语音、F9 双空间呈现、
  F10 设置；
- **当前明确不做**：云同步/远程访问、移动端、插件市场、多用户协作。

## 7. 关键术语

| 术语 | 含义 |
| --- | --- |
| 角色（character） | 由角色卡驱动的对话 AI，说人话、不直接操作项目 |
| 古代机器 / 助手（assistant） | 本地编程助手，执行真实项目任务 |
| 委派（delegation） | 角色在台词中携带的结构化任务/修改指令 |
| 协作模式 | 允许角色委派、允许读取项目的能力边界 |
| 聊天模式 | 角色能力边界：不能读取或操作项目 |
| 回合（turn） | 一次提交 → 一次执行的生命周期单元 |
| 引擎 | 编程助手背后的执行体（Codex app-server / reasonix ACP） |
