# V0.3.9 契约冻结

> 版本：contract-v1
> 冻结基线：`072d17e9f14602d3f61c2e2d0bc775234596a0cb`
> 适用阶段：S1 至 S3。真实供应商和真机结果须另行记录，离线夹具只证明协议与状态逻辑。

## 1. 权威来源与身份

Python Sidecar 是业务状态权威。`conversation.open` 是指定聊天的只读快照，不改变服务端 `current_conversation_id`；桌面各窗口的 `activeConversationId` 是本地视图状态，两者不得互相覆盖。`app.bootstrap` 返回服务端当前项目、当前聊天及全量 `active_tasks`；`conversation.open` 返回目标聊天的消息、工具、运行、队列、审批、摘要和记忆状态。重连后先应用同一 `stream_id` 的快照，再从快照 `sequence` 后消费事件。旧代际不得覆盖新代际。

事件归属至少包含已有的 `account_id/project_id/conversation_id/turn_id/task_id/engine_turn_id/sequence/stream_id` 中适用字段。切换聊天只改变视图，不改变后台任务归属。`updated_at` 是聊天最近持久化业务变化时间，列表排序使用它；消息和工具在统一时间线中优先使用非空 `timeline_order`，旧记录缺失时按 `created_at, message_id/tool_call_id` 稳定排序。不得用 SQLite rowid 作权威顺序。

搭档身份使用 `pair_id`，远程设备鉴权继续称“设备配对”，协议中不得新增含义含混的 `pairing_id`。

长期记忆作用域：

`account_id + project_id + pair_id + character_ref + assistant_identity`

`character_ref` 由服务端从聊天解析：自定义角色为 `card:<character_card_id>`，内置角色为 `builtin:<pair.character.id>`。`assistant_identity` 必须在每次读写时从该聊天绑定的权威搭档配置解析为当前 `pair.assistant.id`，并与记忆记录一同持久化、参与唯一键和查询过滤；`pair_id` 不可替代助手身份。客户端只传 `conversation_id`，不得自行拼接作用域。相同账号、项目、搭档、角色和助手才可跨聊天共享；任一分量不同均不得默认共享。同一 `pair_id` 的配置更换 `assistant.id` 后，不得自动读取或写入旧助手身份下的记忆。项目为空的日常聊天不读写长期记忆。角色卡删除后原作用域保留为孤立数据并明确提示，不得静默并入内置角色。活跃会话复用键必须包含 `project_id + pair_id + character_ref + assistant_identity`。

## 2. 原文、摘要、投影与记忆

`messages` 和 `tool_runs` 永久保存原文及真实结果，不截断、不改写。持久化投影只引用 `message_id/summary_id/tool_call_id`，不复制原文。摘要键只含 `conversation_id`，不得跨聊天读取。

角色消息计数只统计 `source=user|character`、`origin!=character_delegation` 且正文非空的最终消息；流式 delta、助手、工具、思考、系统状态不计数。自上次成功摘要覆盖终点之后达到 80 条，或这些消息 UTF-8 正文累计达到 256 KiB，任一先到即启动压缩。触发后保留最近 12 条符合该定义的原文进入角色上下文；其余已覆盖原文仍留在数据库。摘要必须覆盖连续、已最终落库的消息区间。

摘要由配置的真实模型生成结构化对象，至少含 `summary_id/conversation_id/covers_from_message_id/covers_to_message_id/covers_message_count/content/provider/model/status/error/created_at/updated_at`。代码只校验 JSON 结构、身份、连续区间和安全边界，不使用关键词或正则判断语义，不改写模型摘要。状态为 `idle|running|completed|failed`。失败保存原始错误，保留原投影，不生成空摘要。`summary.regenerate` 只针对真实存在的失败记录或用户显式请求，仍调用真实模型；没有真实恢复能力时 UI 不显示恢复按钮。

长期记忆由模型从明确作用域内的对话提取，内容由模型负责。代码只验证结构与作用域。记录状态为 `active|deleted`，支持真实的 list/update/delete；修改和删除必须持久化并广播。容量超限时交给模型重写，代码不得按关键词筛选或静默截断。

角色装配顺序：角色框架、标准角色字段、world book before/after、HSR 扩展、聊天摘要、配对记忆、事件触发、最近原文与 depth 注入、任务进度/结果及项目运行上下文。世界书扫描只使用投影保留的真实 user/character 原文，不扫描摘要或记忆。助手 `developer_instructions` 始终是配置中的单一助手 Markdown，摘要和记忆不得混入；助手线程内部历史不受角色投影伪装修改，重建时只使用真实支持的引擎接口。

摘要和记忆状态通过非消息状态条展示。`system.summary` 仅用于持久化投影引用的摘要记录，`system.error` 用于真实消息级错误；两者不得承载隐藏提示。失败状态可展开原始错误。

事件：`summary.started/completed/failed`、`memory.updated/deleted`。事件携带 account/project/conversation/pair/character_ref/assistant_identity 与记录 id；失败事件额外携带 `error_code/error`。

## 3. 运行快照与本地未读

服务端为每个聊天提供：当前 turn 及其代际、活动任务、队列、待审批、最近失败和完成终态。`active_tasks` 是全账号权威集合；`active_task` 仅是当前或目标聊天的兼容视图。桌面和移动 store 必须消费 `turn.started/turn.status_changed`，按 `conversation_id` 存放，不得退化为单个全局任务。

审批栏只显示当前聊天的全部 pending；其他聊天只显示计数与导航入口。`ApprovalBar` 不得使用全局 `pending[0]`。消息 `failed/cancelled` 必须显示真实终态及错误，不得吞掉命令失败。

未读只在客户端本地派生，键为 `conversation_id + message_id`。后台聊天收到新的最终 `character` 或 `assistant` 消息时计数；delta、工具、思考和系统事件不计数；进入该聊天即清零。本版不承诺跨设备或重启保存未读。通知点击只有取得真实回调并按 `conversation_id` 跳转才算支持，否则显示平台限制并列入真机待验。

非聊天视图隐藏发送区，保留返回运行中聊天的入口。休眠只有存在真实电源状态源时单独展示；无该来源时按断连展示。

## 4. 增量持久化与性能

普通增量最多 50 条或 50ms 形成一个非空事务，任一先到即刷盘。同一批内按调用顺序写，同一主键保留最后状态；每个受影响聊天只更新一次 `updated_at`。消息更新使用 `ON CONFLICT DO UPDATE`，不得用 `INSERT OR REPLACE` 改变稳定顺序。

用户提交确认、摘要/记忆完成或失败、审批、取消、回合/任务终态、账号切换和正常退出必须强制刷盘。退出刷盘失败须向调用链原样暴露，不能把退出写成成功。进程被强杀时最多损失尚未到 50ms 的普通增量，重启不得合成丢失数据。

统一样本：2 个项目，每项目 2 个聊天，每聊天 500 条混合历史消息；突发样本每聊天连续注入 2000 个普通增量事件，定时样本按每 75ms 注入 1 条，共 400 条。两类样本都要求零丢失、稳定顺序和所有终态可从新连接读取。突发事务上限为 `ceil(普通增量数/50)+关键强刷次数`；定时样本记录实际非空 50ms 刷新批次数加关键强刷次数，不套用突发公式。记录测试机器 CPU、内存、磁盘、三轮中位数。批内单条均摊目标不高于 0.1ms，单聊天 500 条打开目标不高于 200ms；前端虚拟化阈值按实测决定。

## 5. 指标与诊断

`TurnMetric` 至少包含 identity、turn_kind、turn/task/engine id、provider/model/engine_type/reasoning_effort、status、started/first_event/completed 时间、duration、input/output/total tokens、tool_rounds、compression_count、approval_count、failure_type/failure_message、origin 和远程设备标识。未观测或供应商不提供的字段必须为 `null` 且键仍存在；真实零值使用 0。禁止用字符数估算 token。

`metrics.query` 是显式只读查询，支持 account/project/conversation/pair/status/时间过滤和 cursor 分页，默认 50、上限 200。`diagnostics.prompt_assembly` 是显式只读查询，默认只返回模块名称、字符范围、hash、摘要和记忆是否注入及既有 diagnostics；只有用户显式请求隐藏内容才返回原文。诊断不广播隐藏提示，不写入普通聊天。界面使用显式按钮打开可关闭抽屉，关闭后清除抽屉内隐藏内容。

## 6. 语音、租约、PCM 与审批

桌面 `SpeechQueue` 使用单调 epoch。用户发送、新角色完整消息、显式停止/跳过/切换/远程认领都会先增加 epoch，再停止播放器、清队列并关闭在途合成迭代器；旧 epoch 的迟到 PCM 永不写入。partial delta 只能触发抢占反馈，不能直接送 TTS。仍只有角色自然语言可朗读。

远程控制租约按 `device_key` 独立记录，TTL 为 45s，断连重连宽限 15s，最晚 60s 回收。已鉴权持有者的 ping 和 claim 刷新租约；release 和 token 撤销立即回收对应设备，不误释放其他设备。断连不立即释放，宽限结束后过期。控制期间未进入桌面队列的消息不补播。`remote_control` 快照和 `remote.control_changed` 事件提供 state、device_key、expires_at、grace_expires_at 与 reason；无值使用 null。移动连接详情展示租约，失去控制权给轻提示。

移动 PCM 上限保持 14,400,000 bytes，即 24kHz、s16le、300s。超过上限时整条播放进入 `failed`，`error_code=pcm_overflow`，清空缓冲、记录终态、请求服务端停止合成；迟到 chunk/end 不得复活，不丢旧片段后继续播放。播放失败必须显示可见错误。

审批超时保持 600s。统一 `approval.resolved`：`decision=allow|allow_for_conversation|deny|timeout`，并包含 `approval_id/conversation_id/task_id/resolved_by/actor/reason/resolved_at/error_code`；字段缺失保持 null，不伪造 desktop 或 remote。timeout 只能由服务端产生，首个终态获胜，迟到点击返回带真实终态的 `approval_already_resolved`。命令错误除该幂等终态外均须显示或抛出。

## 7. 命令、事件和恢复边界

新增命令：`summary.get`、`summary.regenerate`、`memory.list/update/delete`、`metrics.query`、`diagnostics.prompt_assembly`、`remote.control_status`。补齐已有 `ping`、`remote.claim_control`、`remote.release_control` 的 TS 类型。

新增事件：`summary.started/completed/failed`、`memory.updated/deleted`、`remote.control_changed`、`voice.playback_interrupted`。补齐已有 `voice.mobile_tts_failed`。普通对话不显示诊断隐藏内容。

错误码至少包括 `summary_provider_error/summary_invalid/summary_timeout/memory_scope_mismatch/memory_not_found/pcm_overflow/approval_timeout`。错误保留原始 message，不合成成功或空结果。

## 9. 离线样例

`summary.failed`：`{conversation_id:"c1", summary_id:"s1", status:"failed", error_code:"summary_timeout", error:"provider timeout"}`。失败后投影仍引用原消息。

`approval.resolved` 超时：`{approval_id:"a1", conversation_id:"c1", task_id:"t1", decision:"timeout", resolved_by:"system", actor:"system", reason:"等待审批超时", resolved_at:"2026-01-01T00:00:00Z", error_code:"approval_timeout"}`。

`TurnMetric` 未返回 token：`{input_tokens:null, output_tokens:null, total_tokens:null, tool_rounds:0}`。null 与 0 含义不同。

这些样例用于协议与组件离线测试，不构成真实链路通过证据。
