## 4. B-01 沙盒方案

本机现状（2026-09-10 实测）：WSL2 已安装且含 Ubuntu 发行版；Hypervisor 已启用；当前会话**非管理员**；`C:\Windows\System32\WindowsSandbox.exe` **不存在**，Windows 沙盒不可用。

### 4.1 首选：进程级网络沙盒（本地 TCP 转发器 + `HTTPS_PROXY`）

思路是把「断网」下沉到本机一个可控的 TCP 转发器，用环境变量把候选的出站流量引过去，再按需要掐断它。全程不需要管理员权限，且可一键还原。

- **实现**：复用 `tools/run_a14.py` 中已有的 `TcpProxy`（`start()` / `cut()` 通过 `writer.transport.abort()` / `stop()`），扩展为 `tools/net_sandbox.py`，固定监听本机端口并把上游指向 `api.deepseek.com:443`。
- **接入**：为启动候选的用户会话设置 `HTTPS_PROXY=http://127.0.0.1:<port>`（用户级，非机器级，可 `setx` 还原或仅在测试进程环境内注入）；启动 EXE 前完成设置，结束后清除并核对已清除。
- **四种故障形态**（对应补充测试要求的错误注入）：

  | 形态 | 沙盒动作 | 产品侧应观察到的现象 |
  | --- | --- | --- |
  | 连接被拒 | 转发器停止监听（`stop()`） | 连接失败，错误可定位到连接阶段 |
  | 连接被重置 | 已建立连接上 `cut()` | 传输中断，错误可定位到传输阶段 |
  | 卡住/超时 | 暂停转发不关闭 | 请求悬挂至超时，超时原因可见 |
  | 名称解析失败 | 转发器改为解析不可达主机名并返回失败 | 解析阶段失败，区别于前三种 |

- **验证前提（执行时先确认，不成立则改用 4.2）**：候选的 HTTP 客户端是否读取代理环境变量。若读取，`HTTPS_PROXY` 即可生效，且**无需**写 `dialogue.base_url`——这一点很关键，因为 V039-S4-014 已证明 `base_url` 写入会被静默改写，走配置改端点在该缺陷修复前不可靠。
- **隔离性说明**：沙盒只影响被设置环境变量的进程，不影响主机其他程序；测试结束后必须清除环境变量并留证。

### 4.2 备选：WSL2 内断网

WSL2 自带独立网络命名空间，`wsl -u root` 免 Windows 管理员即可 `ip link set eth0 down` 或 `iptables -A OUTPUT -j DROP`，断网与恢复都是秒级、可脚本化。

- **前提**：候选 Sidecar 需能在 Linux 下启动。执行前先做一次最小启动探测（`python -m pair_harness.desktop_backend --help` 及真实启动）。
- **限制**：Sidecar 含 Windows 专有路径（电源状态、音频设备等）；若启动探测失败，本备选作废，不强行改造候选。
- 若可用，本方案对「DNS 失败」形态更真实（可在 WSL 内改 `/etc/resolv.conf` 指向无效解析器）。

### 4.3 兜底

一次性提升权限的会话或 Hyper-V 虚拟机（Hypervisor 已启用）。仅当 4.1 与 4.2 均不成立时启用，并在 `result.json` 中说明前两种方案失败的具体原因。

## 5. B-03 Codex 剥离：开发交付与复测验证

**开发轨交付**（修复批次，本计划不执行）：

1. 移除对 Responses API 的依赖与相关校验，产品只支持 OpenAI Chat Completions 兼容端点。
2. 供应商切换不再因缺少 Responses 后端而拒绝；不再出现「codex 引擎要求 Responses API 后端…」这类提示。
3. 不再向用户暴露实际不可用的 Codex OAuth 入口（要么移除，要么明确标注不可用，不得留下点了没结果的路）。

**复测轨验证**（本轮执行）：

- 以现有 DeepSeek（Chat Completions）端点为唯一真实供应商，跑通委派全链路：角色自然语言 → 结构化委派 → 多轮工具 → 真实审批 → 文件落盘 → 助手结果摘要 → 角色终局回复。
- 断言出口：全链路成功后报告中不出现终态错误（覆盖 V039-S4-009）；工具执行与审批在工作台与落库可逐条追踪。
- 负向断言：仓库内不存在要求 Responses 的路径或提示；供应商切换不再被 Responses 拒绝；不可用的 OAuth 入口不再出现。
- 成本口径：不引入新付费供应商，全部走既有已授权端点。
