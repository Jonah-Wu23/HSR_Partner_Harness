# HSR Partner Harness V0.3.0 详细实现计划（双 AI 并行开发版）

本文档把 `docs/V0.3.0-V0.6.0 Plan.md` 中 V0.3.0 一节展开为可直接执行的实现计划。开发由两个 AI 并行完成：

- **强逻辑 AI（下称 B 侧）**：Python Sidecar、pair YAML、协议契约、音色复刻、测试与打包验证。
- **强视觉 AI（下称 F 侧）**：角色卡与助手卡、desktop 前端（Tauri 2 + React）、主题与视觉资源、搭档选择 UI、前端测试与安装包验证。

## 1. 范围与不做事项

### 1.1 本期范围

- 新增两组搭档："流萤 × 萨姆"、"三月七 × 第四面镜"，含角色卡、助手设定、主题、头像/图标和语音配置。
- 增加搭档目录与选择入口：新建聊天时选择搭档；已有聊天按自身 `pair_id` 恢复；切换项目或重启后不串角色。
- 三组搭档（含现有"白厄 × 神秘的古代机械"）共用现有委派、审批、编程引擎、标题、语音和双空间消息管线，不为新角色复制业务逻辑。
- 同步所有正式版本号为 0.3.0，并生成 NSIS 安装包。

### 1.2 明确不做

以下事项属于 V0.4.0 及以后，本期一律不碰：

- `recent_roleplay_context()` 的 `target` 修复、`last_active_conversation_id`、`_message()` 写库顺序修复。
- usage 指标、`turn_metrics`、前缀指纹、prompt golden snapshots、诊断命令。
- 持久化上下文投影、会话摘要、跨聊天角色记忆。
- 流式 delta 合并、delegate tool call、429/503 重试。
- Reasonix EP v1、审批链收敛、Pi。
- 向量数据库、HTTP/SSE、Node 运行时。

### 1.3 提交纪律

- 不使用 `git add -A`，提交时写明文件路径。
- V0.3.0 的搭档接入不得与任何 V0.4.0 优化混入同一提交。
- `.archive/` 受 Git 忽略，旧版文件放那里。

## 2. 现状锚点（代码事实，行号以写作时为准）

### 2.1 pair 配置

- pair 定义文件：`config/pairs/{pair_id}.yaml`，现有 `phainon_ancient_machine.yaml`、`reviewer.yaml`（内部审查用，本期不动）。
- 加载器：`src/pair_harness/config/pairs.py`。
  - `PairConfig`（pairs.py:31-37）：`pair_id / character / assistant / theme`。
  - `NamedSpeakerConfig`（pairs.py:10-16）：`id / name / prompt / voice_id`。
  - `PairTheme`（pairs.py:19-28）：7 个颜色字段（`character_text / character_primary / character_deep / character_active / assistant_primary / assistant_bright / assistant_shadow`）。
  - 三个模型都是 pydantic `extra="forbid"`：**YAML 多加任何字段会直接验证失败**。
  - `load_pair_config(pair_id)`（pairs.py:50-66）：读 YAML，强校验 `pair_id` 与文件名一致、两个 prompt 文件存在。
  - `repository_root()`（pairs.py:44-47）：PyInstaller frozen 时取 `sys._MEIPASS`。
  - `adopt_voice_id()`（pairs.py:78-116）：单行改写 voice_id；`demo-` 前缀为占位音色（pairs.py:75 `PLACEHOLDER_VOICE_PREFIX`），占位可被覆盖，真实音色需 `force`。
- **当前不存在 pair 目录/列表机制**：数据模型无 catalog，协议无 `pair.list` 命令。

### 2.2 prompt 组织

- 角色卡示例：`config/prompts/characters/phainon.md`（95 行）。结构：`# 名称` → `## 身份` → `## 世界观` → `## 性格与对用户的关系` → `## 怎么说话`（含"speech 会进语音朗读，只写纯台词"）→ `## 语言禁区` → `## 执行边界与委派` → `## 示例`（8 组对话）。
- 助手卡示例：`config/prompts/assistants/ancient_machine.md`（49 行）。结构：`# 名称` → `## 身份` → `## 怎么说话` → `## 权限边界` → `## 与白厄的分工` → `## 语言要求` → `## 示例`。
- 委派的 JSON 形态由运行时"输出协议"统一注入，**不写进角色卡**；角色卡只写职责边界。
- 四份新增角色卡与助手卡由 F 侧编写，B 侧只在 pair YAML 中引用并负责加载校验。
- 注意：助手卡的"与白厄的分工"是硬编码搭档名，新助手卡必须各自写分工段，**不可原样复用 ancient_machine.md**。

### 2.3 语音链路

- voice_id 直接写在 pair YAML 的 `character.voice_id` / `assistant.voice_id`，无独立映射表。
- 音色复刻脚本：`scripts/create_qwen_voice.py`，子命令 `clone`（声音复刻，参考音频默认 `assets/reference_voices/白厄`）、`design`（默认提示词 `config/voices/ancient_machine_prompt.txt`）、`adopt`（把 voice_id 写回 pair YAML）。
- TTS 适配器：`src/pair_harness/adapters/audio/qwen_tts.py`（DashScope `tts_v2` streaming，24 kHz PCM）。
- 朗读策略：`src/pair_harness/core/voice_policy.py`——仅角色台词与助手自然语言进 TTS，工具记录天然静音。
- 音色按消息来源取当前 pair 的 voice_id：`src/pair_harness/core/voice_runtime.py:351-357`；`voice.preview` 只允许 pair 内置两个音色（`application_service.py:974-982`）。
- 前端不播放音频，TTS 合成与播放全在 Python 侧；前端只有 `VoiceMiniPlayer` 状态可视化。

### 2.4 协议与聊天绑定

- Sidecar 入口：`src/pair_harness/desktop_backend/__main__.py`（`--pair` 默认 `phainon_ancient_machine`）；路由 `router.py`；服务主体 `application_service.py`（`handle_command` 第 414-460 行分发）。
- 协议形态（`protocol.py`）：请求 `{kind:"request",id,method,params}`；响应 `{kind:"response",id,ok,result|error}`；事件 `{kind:"event",event,sequence,payload}`，序号单调。
- 命令全集 44 个（`commands.py:7-49`），**没有 pair 列表/选择命令**。
- pair 随 bootstrap 下发：`application_service.py:350` `"pair": self._pair_payload(...)`；`_pair_payload`（1816-1830）含 `pair_id/character{id,name,voice_id}/assistant{...}/theme`。
- `conversations` 表有 `pair_id TEXT NOT NULL`（`storage/schema.sql:64-73`），无外键（pair 只活在 YAML）。
- `conversation.create` / `project.create` 已接受 `params.pair_id`（`application_service.py:587-597`、488-491），缺省为启动 `--pair`，**但不校验 pair 是否存在**。
- 选中聊天时按会话重载 pair 的运行时已就绪：`application_service.py:1661-1687` `_select_conversation_context`（重载 PairConfig、重建 orchestrator、`voice_runtime.set_context`）。

### 2.5 前端

- 状态管理：zustand 单 store（`desktop/src/stores/desktopStore.ts`）；事件经 `eventBatcher.ts`（40ms 合批）入 store；`presenters/presenters.ts` 是唯一 ViewModel 映射点；`ui/` 只消费 ViewModel，不碰协议。
- 新建聊天：`desktop/src/ui/navigation/ChatColumn.tsx:270-278`，直接 `actions.createConversation(projectId)` → `conversation.create { project_id, title }`，**无搭档选择环节，参数不带 pair_id**。
- 搭档标识：会话列表 `pair-chip` = 两个 CSS 色点（`ChatColumn.tsx:147-155`，`app.css:182-183`），读的是 `navigation.currentPair`（全局唯一搭档），**不是按会话的 pair**；**全前端零头像资产**。
- 主题：CSS 变量在 `styles/tokens.css`（`[data-theme="dark"|"light"]`），白厄色组硬编码其中（tokens.css:73-79、131-137）。扩展点已预留：`AppShell.tsx:62-64` 注释明确"不做 PairRecord.theme 内联注入……多搭档配色接入时在令牌层统一扩展"。
- 协议类型：`contracts/protocol.ts`（命令枚举 230-270、事件枚举 287-313、`PairRecord` 154-169、会话记录含 `pair_id` 第 140 行）。
- mock：`desktop/src/mocks/scenarios.ts`（19 个场景，搭档硬编码 `phainon_ancient_machine`，41-58 行）+ `services/mockDesktopBackend.ts`（完整行为模拟）。纯浏览器 dev server 自动用 mock；`preview.html?scenario=...` 可做视觉预览。
- 测试：`npm test` = vitest（jsdom），11 个测试文件；**7+ 个文件硬编码"白厄"名字和主题色值**（presenters.test.ts、AppShell.test.tsx 等），新增搭档会破坏断言。

### 2.6 打包与版本号

- sidecar 打包：`desktop/scripts/build-sidecar.ps1:30-41`，PyInstaller onedir，`--add-data` 包含整个 `config/`、`assets/`、`schema.sql`。**新 pair 只要往 `config/` 加文件就自动进包，无需改构建脚本。**

## 4. 接口契约（冻结，两侧共同遵守）

### 4.1 pair_id 与文件命名

- 新搭档一：`firefly_sam`（流萤 × 萨姆）→ `config/pairs/firefly_sam.yaml`。
- 新搭档二：`march7_fourth_mirror`（三月七 × 第四面镜）→ `config/pairs/march7_fourth_mirror.yaml`。
- 文件名与 YAML 内 `pair_id` 必须一致（`load_pair_config` 强校验）。
- prompt 文件：`config/prompts/characters/firefly.md`、`config/prompts/characters/march7.md`、`config/prompts/assistants/sam.md`、`config/prompts/assistants/fourth_mirror.md`。
- 角色/助手 id：`firefly`、`march7`、`sam`、`fourth_mirror`；显示名：流萤、三月七、萨姆、第四面镜。

### 4.2 协议新增

**bootstrap 响应增加搭档目录**。`app.bootstrap` 的 result 在现有字段基础上增加：

```json
{
  "pairs": [
    {
      "pair_id": "phainon_ancient_machine",
      "character": { "id": "phainon", "name": "白厄", "voice_id": "qwen-..." },
      "assistant": { "id": "ancient_machine", "name": "神秘的古代机械", "voice_id": "qwen-..." },
      "theme": { "character_text": "#...", "...": "..." }
    }
  ]
}
```

- `pairs` 为 `PairSummary[]`，形状与现有 `_pair_payload` 输出完全一致（即目录中每项就是一个 pair payload）。
- 目录顺序 = 配置文件名字典序；现有 `pair` 字段（当前生效搭档）保留不变，向后兼容。
- `reviewer.yaml` 属于内部审查智能体，**不进入 `pairs` 目录**。过滤规则：目录只包含 `firefly_sam`、`march7_fourth_mirror`、`phainon_ancient_machine` 三个的允许列表，后续新增搭档时显式加入。

**`conversation.create` / `project.create` 的 `pair_id` 校验**：

- `params.pair_id` 省略时行为不变（缺省为启动 `--pair`）。
- 提供的 `pair_id` 不在目录允许列表内时，返回 `ok:false`，error code `PAIR_NOT_FOUND`，message 含传入的 pair_id；不创建任何记录。

**会话与搭档的关联**：会话记录沿用现有 `pair_id` 字段（协议与 DB 均已有），前端按 `pair_id` 自行 join `pairs` 目录取名字、主题、头像。协议不为会话记录追加冗余字段。

**TypeScript 类型**（`desktop/src/contracts/protocol.ts`，B 侧改）：

```ts
export interface PairSpeakerSummary {
  id: string;
  name: string;
  voice_id: string;
}

export interface PairSummary {
  pair_id: string;
  character: PairSpeakerSummary;
  assistant: PairSpeakerSummary;
  theme: PairTheme; // 复用现有 PairRecord["theme"] 的形状
}

// BootstrapResult（现有 bootstrap result 类型）增加：
//   pairs: PairSummary[];
```

### 4.3 头像资源约定（不走协议）

- 存放路径：`desktop/src/assets/pairs/{pair_id}/character.png` 与 `desktop/src/assets/pairs/{pair_id}/assistant.png`。
- 共 6 张：三个 pair × 两个说话方。图片由用户提供，F 侧负责接入。
- 规格：正方形 PNG，源图 ≥ 256×256，前端以 1x/2x 显示尺寸渲染；文件名固定 `character.png` / `assistant.png`，不带哈希。
- 前端按 `pair_id` 静态 import 映射（Vite 打包进 bundle）；后端对头像零感知，协议不含头像字段。
- 用户图片未到位前，F 侧先放占位图（纯色块 + 名字首字），路径与命名不变，到位后直接替换文件。

### 4.4 主题机制

- 按 `AppShell.tsx:62-64` 既定扩展点，在令牌层扩展，**不做运行时内联注入**。
- `tokens.css` 中把 pair 七色从全局变量改为按 `[data-pair="..."]` 作用域声明：

```css
[data-theme="dark"][data-pair="phainon_ancient_machine"] {
  --pair-character: #8AA4D4; /* 现有白厄色组原样保留 */
  /* ...七色全套... */
}
[data-theme="dark"][data-pair="firefly_sam"] { /* 流萤组七色 */ }
[data-theme="dark"][data-pair="march7_fourth_mirror"] { /* 三月七组七色 */ }
/* light 同结构各一套 */
```

- `AppShell.tsx` 根节点增加 `data-pair={vm.currentPairId}`；`currentPairId` 取**当前选中会话的 pair_id**，无选中会话时取当前项目默认/全局 pair。
- 七色与 `PairTheme` 字段一一对应：`character_text / character_primary / character_deep / character_active / assistant_primary / assistant_bright / assistant_shadow`。YAML 中的 theme 值与 tokens.css 色值保持同一份设计稿（F1 产出，B1 填入 YAML）。
- 语义：pair 主题跟随**当前查看的会话**切换，打开不同搭档的聊天即换色组；这正是"切换项目或重启后不串角色"的视觉表达。

### 4.5 新建聊天的搭档选择

- 入口：`ChatColumn.tsx:270-278` 新建聊天按钮 → 弹出搭档选择层（用现有 `ui/primitives/Menu.tsx` 或同级弹层，不引入新组件库）。
- 选择层展示目录中每组搭档：双头像（或占位图）、`角色名 × 助手名`、七色中的两个主色点。
- 选定后调用 `conversation.create`，params 带 `{ project_id, title, pair_id }`。
- 默认选中项：当前选中会话的 pair_id；无选中会话时用目录第一项。选择记忆**不做持久化**（保持简单，后续版本再议）。
- 已有聊天不出现"换搭档"入口；搭档只在创建时确定。

### 4.6 语音契约

- 三组搭档的 voice_id 都写在各自 YAML。白厄组已有真实音色，不动。
- 新两组在用户提供参考音频前，YAML 写 `demo-` 占位（`demo-firefly`、`demo-sam`、`demo-march7`、`demo-fourth-mirror`），链路可跑、朗读静默属预期。
- 用户提供参考音频后，B 侧执行 `scripts/create_qwen_voice.py clone` 复刻并 `adopt` 写回 YAML（占位音色允许被覆盖，无需 force）。
- `voice.preview` 与语音设置页按**当前会话的 pair**展示和试听两个音色（现有逻辑已按 pair 取音色，F 侧确认展示正确即可）。

## 5. 强逻辑 AI 任务包（B 侧）

每包格式：目标 / 改动文件 / 步骤 / 验收。除标注依赖外，包内有序、包间可并行。

### B1：两个 pair YAML

### B2：pair 目录加载 + bootstrap 下发 + pair_id 校验

- **目标**：契约 4.2 的后端落地。
- **改动文件**：`src/pair_harness/config/pairs.py`、`src/pair_harness/desktop_backend/application_service.py`。
- **步骤**：

## 10. 风险与注意点

- **助手卡分工文案不可复用**：`ancient_machine.md` 含"与白厄的分工"硬编码，新助手卡必须各自撰写，提交前全文检索"白厄"确认无残留。
- **`extra="forbid"`**：pair YAML 只允许既定字段；头像不进 YAML（走前端资源约定 4.3），避免验证失败。
- **前端测试债**：硬编码白厄的断言是本次必须还清的债（F6），否则新增搭档后 CI 全红。
- **占位音色静默**：`demo-` 前缀音色下 TTS 不出声是预期行为，验收语音身份时不要误判为 bug；B3 完成前语音相关验收标注"占位"。
- **目录允许列表**：`reviewer.yaml` 不进 `pairs` 目录；新增 pair 必须显式加入 `PAIR_CATALOG_IDS`，防止内部配置泄漏到 UI。
- **启动 fail fast**：目录中任一 pair 加载失败即启动报错，宁可启动失败也不带病运行（避免某会话恢复时才发现 pair 缺失）。
- **主题跟随会话**：`data-pair` 取当前选中会话的 pair_id，不是全局状态；打开历史会话时色组随之切换是设计意图。
- **不维护双份色值**：F1 产出的三组七色是唯一设计稿，tokens.css 与 pair YAML 从同一份清单填值，后续改色先改清单。
