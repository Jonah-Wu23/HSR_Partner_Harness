## 1. 新发现与修复

| 问题 | 原代码行为与影响 | 本轮处理与证据 |
| --- | --- | --- |
| 连续语音无法接续 | A 播放时 B 已收完，B 的结束信号被忽略；A 结束后只置 idle，B 永久留在缓冲 | 按消息保存结束信号，完成、停止或失败后接续待播消息。`voiceQueue.test.ts` 的首批四个用例在原代码全部失败，修复后通过 |
| 语音失败跨消息覆盖 | A 的迟到合成失败会把正在播放的 B 置 failed；一次 failed 后新消息也无法启动 | 终态隔离、等待消息失败仅清理自身、允许后续消息启动；错误保留日志。补齐六项语音队列回归 |
| 重连遗漏控制声明 | bootstrap 的活跃聊天分支提前 return，没有执行 claim；claim 失败被空 catch 吞掉 | 所有 bootstrap 分支必须等待 `remote.claim_control` 成功；失败不公布同步完成 |
| 配对与连接竞态 | 在 auth_failed 的 OPEN socket 上重新配对成功后仍保持 auth_failed；旧 socket 的迟到关闭回调可清空新连接 | 新凭证的 bootstrap 与 claim 成功后恢复鉴权状态；回调绑定实际 socket 实例，断连作废旧同步代次 |
| 控制释放回执缺失 | 直接断连无法区分暂时断网与明确退出；不等待 release 会遗留错误或丢失控制归属 | 稳定设备身份持有控制权，临时断网保持桌面静音；明确 release 或撤销设备才释放。手机等待释放成功后清凭证；服务确认 unauthorized 时允许清除失效凭证，其他错误可见且保留凭证 |
| 旧语音运行时监听器残留 | 注册闭包后仍用 `old_runtime.on_message` 解绑，重建后旧监听器继续接收消息 | 改为可正确解绑的服务实例回调；回归用例先证实旧实现失败 |
| 本地试听绕过静音 | 自动朗读被阻止，但手动重播、试听入口仍可发声 | 控制期间明确返回 `remote_playback_active`；释放后的迟到手机 stop 不误停桌面新播放；停止调用使用异步接口 |
| Android IPC client 身份错误 | 另建 RustWebViewClient，但 IPC 仍持有旧实例，旧实例的 currentUrl 不再随页面更新 | 包装 Wry 已安装的原 client，保持资源处理、页面回调和 IPC 使用同一实例 |
| 后台探活误判与恢复重复 | onPause 后探活计时器仍运行，后台 JS 挂起可能触发恢复；旧回调可能污染新探测 | onPause/onDestroy 取消计时器，隔离迟到回调；渲染退出与超时统一一次性清理、恢复入口 |
| Android 构建可静默复用旧库 | Gradle 仅见 `.so` 存在就跳过 Rust 构建；Tauri custom-protocol 的前端也编译在该库内，仅检查 APK assets 不足 | 新增 `desktop/scripts/build-android.ps1`，先构建前端与 Rust，再向 Gradle 交付明确校验的库；删除按文件存在自动跳过的分支 |

## 2. 原生异常核查

Windows first-chance 观察器仅记录异常并返回 `EXCEPTION_CONTINUE_SEARCH`，没有处理或屏蔽异常。记录到访问异常来自 `.venv/Lib/site-packages/PyQt5/Qt5/bin/MSVCP140.dll + 0x12ea0`，读取地址为零。该 DLL 版本为 `14.26.28720.3`；系统和打包 Sidecar 使用的 DLL 均为 `14.51.36247.0`。

环境中注册了 `pytest-qt` 自动加载插件，而仓库没有 PyQt/pytestqt 测试或业务代码。独立进程的真实 ONNX 推理和服务初始化正常；移除 Qt 插件自动加载后，同一回归和完整测试均正常。未改生产 VAD 代码、未跳过 VAD 测试、未关闭 faulthandler。

真实 Silero 模型的零输入推理输出形状为 `(1, 1)`、`(2, 1, 128)`，概率为 `0.04426271`。该检查不访问麦克风或扬声器。

## 5. 交给 G2 的验收边界

- 连续播放至少 10 条，覆盖长短回复交叠、手动停止、合成失败后新消息、停止期间收到下一条音频；同时记录停止请求数量与 UI 响应。
- 手机控制期间检查电脑自动朗读、已排队音频、手动试听和重播均静音；临时断网、锁屏仍保持归属，明确退出或桌面撤销设备后验证恢复。
- 清洁启动只锁屏、播放中锁屏、语音失败后锁屏分别验收；前后台至少 20 次。恢复后验证 WebView 页面、IPC、bootstrap 和实际操作，不能只看 recreate 日志。
- 首次配对、旧凭证失效后重新配对、控制声明失败与网络重连，均检查错误显示与按钮收尾。
- 按原诊断矩阵补齐 C1～C6 的剩余真实路径，尤其锁屏通知去重、委派拒绝/取消/超时、队列失败推进和角色会话复用。

框架核查没有支持“普通 recreate 必然销毁 native 窗口而不可恢复”的猜测：AOSP relaunch 会在销毁前设置配置变更状态，Wry/Tao 保留相应 native 状态并使用保存的 Activity ID 重建。因此本轮没有新增伪造配置状态的兼容分支；恢复可用性仍需 G2 现场证明。
