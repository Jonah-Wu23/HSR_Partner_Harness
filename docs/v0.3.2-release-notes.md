# HSR Partner Harness v0.3.2

v0.3.2 收敛了多聊天执行、助手工作台时间线、Reasonix 只读探索和用户自建语音这几条链路。

## 本版本变化

- 助手的 reasoning、正文和工具卡按真实事件顺序分段保存并混排展示，工具前后的内容不会再被压成一条消息。
- 不同聊天按 conversation 独立运行；同一聊天仍保持队列语义。取消、审批和运行状态按 conversation/task 归属。
- ACP 通知按 Reasonix session 路由，多个 session 的事件不会由错误的消费者拿走。
- Reasonix 只读探索放行复杂 PowerShell 管道、脚本块、变量和命令链；真实写入命令仍由任务权限边界拒绝，命令本身的 stderr 和 exit code 原样保留。
- 语音改为 BYOK：用户在本地账号中填写自己的 DashScope Key 与服务地址，ASR 固定为 `qwen-audio-3.0-asr-flash-streaming`，TTS 与音色生成固定为 `qwen-audio-3.0-tts-flash`。
- 语音页支持五个参考音色复刻和一个声音设计音色的逐项生成、部分成功保存和失败项重试；Key 只显示掩码。
- 删除语音赞助二维码和作者承担语音费用的产品承诺。语音请求直接计入用户自己的 DashScope 账号。
- 单窗口聊天标签和独立聊天窗口使用本地 view id；关闭标签只关闭视图，不取消后台任务。

## 语音使用

首次使用时，在设置 → 语音中填写自己的 DashScope API Key 和服务地址并保存。保存后可先验证 ASR；生成音色时，应用按 manifest 顺序提交五个声音复刻和一个声音设计请求。单项失败不会覆盖已经保存的 voice_id，再次点击只会重试未完成项。

分发运行时不读取或回退到发布者的语音 Key；开发机 `.env` 仅保留兼容入口。没有当前账号生成的音色时，TTS 显示未生成，不伪造 voice_id。

## 参考音频提交方式

五个复刻音色默认读取安装包内参考音频，转为 data URI 后放入 DashScope customization 请求的 `input.url`。这一形态已由真实请求验证成功，不依赖 GitHub Release 或其他公网音频托管。manifest 中的 `public_url` 只保留作发布素材记录和人工排查备用。
