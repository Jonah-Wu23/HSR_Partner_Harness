# HSR Partner Harness v0.4.1

v0.4.1 修复桌面与手机会话在流式更新和长列表中的消息排版问题。新内容到达时，消息卡片按实际高度排列；用户翻阅历史内容时保留阅读位置，回到最新消息后恢复自动跟随。

## 会话消息流

- 桌面角色区、助手工作台和手机聊天页使用同一套动态高度消息列表。消息、工具调用、排队项和思考卡片在内容增长、展开及窗口宽度变化后重新测量，不再依赖固定估高放置卡片。
- 列表采用连续文档流排列虚拟窗口内的行，长会话只挂载可见范围附近的卡片，行高变化不会让相邻卡片叠在一起。
- 默认跟随最新消息。用户上翻后，流式更新与布局调整保持当前阅读位置；滚回底部或使用“回到最新”后继续跟随。持续拖动滚动条也按用户实际位置更新跟随状态。
- 滚动位置由会话列表统一管理。工作台收起期间暂停定位，重新展开后按原有跟随状态恢复阅读位置，只更新已挂载行的高度，其余行继续使用测量缓存。
- 工具卡片和思考卡片的展开状态按会话与消息身份保存，虚拟滚动卸载卡片后再返回仍保留状态。

## 验证

Playwright 使用本地会话数据，在本机 Chrome 中加载桌面和手机的实际 React 组件及生产 CSS。验证覆盖 39/40/41 条边界、500 条消息、工具卡片展开与虚拟化，以及流式更新期间连续 12 帧的消息边界和阅读位置。滚动场景还包括程序滚动、持续拖动、视口尺寸变化与工作台开合；键盘翻阅和触摸点击也纳入跟随状态检查。失败时保留截图、视频和 trace。

本次滚动接入改动的验证结果：桌面相关组件测试 25 项通过，手机相关组件测试 51 项通过；浏览器布局与滚动测试 4 项通过。桌面与手机 TypeScript 检查、生产构建均通过。
