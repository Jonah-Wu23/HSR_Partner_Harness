# HSR Partner Harness V0.4.0 · 数据字段与后端能力清单

> 面向强逻辑 AI 的交付物。以下全部条目均提取自 V0.4.0 视觉原型（角色库 / 快速创建 / 高级编辑 / 世界书 / 导入 / 导出 / 角色语音页面），未包含原型中不存在的字段。原型中的数值（如世界书 12 条、音色 ID `voice_kfk_8f3a21`）均为样例数据，仅说明形态，不代表后端已实现。

## 1. 角色卡数据字段清单

### 1.1 基本信息（快速创建页 · 基础信息区）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 名称 | string | **是**（唯一必填项） | 未填写时阻止完成创建并给出字段级错误提示 |
| 头像 | image | 否 | 未设置时用名称首字符占位；走独立头像流程（选择 / 拖放 / 裁切 / 替换 / 删除） |
| 标签 | string[] | 否 | 回车添加、可逐个删除；用于角色库搜索与筛选 |
| 简介 | string | 否 | 一句话介绍 |

### 1.2 人格设定（快速创建页 · 人格设定区）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 性格 | string | 否 | 上限 2000 字，带字数计数 |
| 对话场景 | string | 否 | 背景 / 时间 / 地点，上限 2000 字 |
| 第一条消息 | string | 否 | 角色开场白（默认问候），上限 2000 字 |
| 示例对话 | string | 否 | 帮助模型把握语气，上限 2000 字 |

快速创建与高级编辑**共享同一份角色卡数据**，模式切换时内容必须保留，不得形成两套互相覆盖的内容。

### 1.3 高级编辑分区（与原始数据 JSON 对应）

按编辑器分树组织，四个分组：

| 分区（分组） | 建议键名 | 类型 | 说明 |
|---|---|---|---|
| 系统提示（基础组） | `system_prompt` | string | 最高优先级注入，约束整个会话行为边界 |
| 历史后指令（基础组） | `post_history_instruction` | string | 插在对话历史之后、最新用户输入之前 |
| 备选问候（基础组） | `alternate_greetings` | string[] | 新会话随机选用一条替代默认问候；样例 3 条，需支持增删 |
| 群组问候（基础组） | `group_greeting` | string | 多角色会话首次发言时使用 |
| 世界书绑定（世界组） | `worldbook` | ref/object | 绑定条目在世界书编辑器统一管理；此处只展示统计（绑定 12 条：常驻 3 / 关键词触发 9），见第 2 节 |
| 世界架构（世界组） | `world_architecture` | string | 世界基本格局，作为背景常识注入 |
| 身份外貌（人设组） | `identity_appearance` | string | 身份与外貌描述 |
| 语言方式（人设组） | `speech_style` | string | 说话风格与口癖 |
| 行为状态（人设组） | `behavior_states` | string | 行为习惯与状态机说明（原型为自由文本，是否结构化待定，见第 6 节） |
| 心理核心（人设组） | `psyche_core` | string | 动机、恐惧与内在矛盾 |
| 用户关系（人设组） | `user_relationship` | string | 与用户的关系设定 |
| 关系阶段（人设组） | `relationship_stages` | string（或结构化） | 阶段定义与推进条件；原始数据中当前阶段示例为 `relationship_stage: "pawn"` |
| 时间线（人设组） | `timeline` | string（或事件数组） | 关键事件时间线，样例含 T-? / T-0 / T+37 天等相对时点 |
| 叙事规则（人设组） | `narrative_rules` | string | 叙事视角与节奏约束 |
| 声音感官（扩展组） | `voice_style_prompt` | string | 语气提示词，供 TTS 合成使用；音色绑定状态只读展示，绑定操作在角色语音页完成 |
| 声明式面板（扩展组） | `declarative_panel` | 行式配置（`字段名 \| 标签 \| 默认值`） | 定义会话内展示的自定义面板字段；当前版本**保留但不运行** |
| 原始数据 JSON（扩展组） | — | object（只读） | 完整 JSON 快照，仅供核对，不支持在页面内编辑 |

### 1.4 原始数据 JSON 顶层结构（原型快照）

```json
{
  "spec_version": "3.0",
  "id": "char_kafka_v3",
  "name": "卡芙卡",
  "source": "created",
  "version": 3,
  "voice": { "bound": true, "profile": "kafka_low_soft" },
  "worldbook": { "entries": 12, "always_on": 3, "keyword": 9 },
  "sections": { "system_prompt": "…", "alternate_greetings": 3, "relationship_stage": "pawn" },
  "updated_at": "2026-08-15T21:40:00+08:00"
}
```

字段说明：`source` 枚举至少包含 `created` / `imported`（角色库另有 `builtin` 内置只读角色与草稿）；`updated_at` 用于角色库「最近编辑时间」展示。

## 2. 世界书条目字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 启用 / 禁用 | boolean | 列表内开关切换；禁用条目视觉置灰 |
| 常驻 / 选择性 | enum | 常驻无条件注入；选择性按关键字触发 |
| 主关键字 | string | 触发关键字 |
| 次关键字 | string[] | 逗号分隔，命中任一即触发 |
| 插入顺序 | number（0–999） | 同位置多条目按此排序 |
| 插入位置 | enum | 角色设定之前 / 角色设定之后 / 对话顶部 / 对话底部 |
| 扫描深度 | number（0–20） | 向上匹配最近 N 条消息 |
| 条目内容 | string | 纯文本，命中后按插入位置原样拼入提示词 |

后端能力要求：条目列表（搜索、拖动排序、虚拟滚动，原型演示 48 条规模）、新增、复制、编辑 / 预览切换、按条保存与放弃更改。角色卡侧需能读取绑定条目的统计信息（总数 / 常驻数 / 关键词触发数）。

## 3. 语音能力

- **固定模型（界面只读，不允许用户修改）**：
  - ASR：`qwen-audio-3.0-asr-flash-streaming`
  - TTS / 声音复刻 / 声音设计：`qwen-audio-3.0-tts-flash`
- **参考音频要求**：WAV / MP3；时长 10–60 秒；单一人声；无背景音乐与明显环境噪声；采样率 ≥ 16000 Hz，单双声道均可；语流自然、含完整句子。
- **公网 URL 注意事项**：TTS 服务要求参考音频可通过公网 URL 访问，创建时由系统自动上传生成临时链接；链接有效期有限，需提示用户上传后及时创建。界面必须有明确提示条。
- **DashScope 账号配置**：未配置 API Key 时进入「账号未配置」态，阻断创建并引导前往设置页。
- **音色 ID 绑定**：创建成功后返回音色 ID（样例 `voice_kfk_8f3a21`），绑定到角色并持久化（对应原始数据 `voice.bound` / `voice.profile`）；支持试听、重新创建、解除绑定；删除角色时一并解绑。
- **创建过程**：通常 20–40 秒，需要进度展示与取消能力。
- **失败处理**：透传真实错误（样例：`TTS 服务返回 402：音色创建额度已用尽`）；失败时不保存参考音频。
- **助手无 TTS**：助手永远不使用 TTS。界面不得出现助手音色设置、助手试听、助手语音开关。

## 4. 导入导出能力

### 4.1 导入

- 支持 `.json`（Character Card v2 / v3）与 `.png`（内嵌角色数据的 PNG 卡片），单文件 ≤ 10 MB；选择或拖放进入。
- **解析在本地完成，文件不上传**。
- 导入预览需展示：角色名称、头像（PNG 内嵌头像直接预览；JSON 缺头像时给出「导入缺头像」标记并允许后续补设）、Character Card 版本徽标、备选问候数量、世界书条目数量、深度提示数量、文件大小。
- **扩展识别分级**：
  - 已识别并随导入启用：世界书、声明式面板、mufy 字段；
  - 已保留但暂未运行：regex 脚本、js_slate 宏——原样存入角色卡，当前版本不执行，后续版本支持后自动生效。
- **名称冲突副本策略**：存在同名角色时弹出冲突确认，默认建议「作为副本导入」（两角色互不影响），或取消导入保持角色库不变。
- **错误摘要透传**：解析失败时展示原始错误（样例 `ParseError: missing field 'spec_version' at line 3`，含调用位置），明确告知文件未被导入、角色库无任何改动；**不得用默认角色或空内容掩盖失败**；失败条目可留存在角色库中供查看错误与移除。
- 导入成功 / 失败均需明确终态，支持重试。

### 4.2 导出

- 两种格式（均包含完整 v3 字段与 mufy 扩展字段，区别在头像承载方式）：
  - **v3 JSON（推荐）**：纯文本，头像不内嵌、以引用方式保留；
  - **v3 PNG**：角色数据嵌入 PNG `tEXt` chunk，头像随图片一体携带。
- 两步流程：选择格式 → 预览导出（文件名可编辑，扩展名随格式联动）。
- 导出前检查清单：头像状态（已嵌入 / JSON 不含头像）、世界书包含数量、扩展字段序列化状态、声明式面板「暂未运行，按原始数据保留」。
- 保存位置展示（样例 `~/PartnerHarness/exports/`）；导出完成给出完整路径。
- 导出失败透传系统错误（样例 `EACCES: 无法写入目录`）并支持重试。

## 5. 状态机汇总

### 5.1 角色库

- 来源筛选：`内置` / `创建` / `导入` / `草稿` / `已归档`。
- 卡片状态：使用中（当前会话角色，置顶条展示）、草稿（未保存更改）、内置（只读，仅「查看」，不适用音色）、导入失败条目（未创建角色，可查看错误 / 移除 / 重试）。
- 音色状态筛选：`已绑定` / `未配置` / `创建中` / `失败`。
- 列表元信息：头像（缺失时用占位 + 警告标记）、名称、标签、世界书条数、最近编辑时间。
- 操作：创建、导入、复制、编辑、导出、归档、删除（删除需确认弹窗：移除全部字段、世界书条目与头像，解绑音色，不可恢复）。
- 空态：无角色 / 筛选无结果（可清空筛选）。

### 5.2 语音五态

`未配置` → `账号未配置`（阻断，引导设置）→ `创建中`（进度 + 可取消）→ `成功`（音色 ID 已绑定 + 试听）/ `失败`（真实错误 + 重试）。取消创建回到「未配置」。

### 5.3 导入五态

待选择（拖放区）→ `解析中`（骨架屏）→ `预览` / `冲突`（名称冲突弹窗）→ `成功` / `失败`（错误摘要 + 重试，角色库不变）。

### 5.4 导出态

选择格式 → 预览（文件名 / 检查清单 / 保存位置）→ `导出完成`（完整路径）/ `导出失败`（系统错误 + 重试）。

### 5.5 编辑器保存态

`未保存更改` → `保存中…` → `已保存 HH:MM:SS`（防抖自动保存）；快速创建草稿每 30 秒自动保存。

## 6. 待后端确认的开放问题

1. **mufy 高级字段的正式数据契约**：人设组各分区（行为状态 / 关系阶段 / 时间线等）目前是自由文本，是否需要结构化 schema？原始数据中的 `relationship_stage` 枚举值集合待定义（样例仅出现 `pawn`）。
2. **备选问候 / 群组问候 / 第一条消息**在会话启动时的选用规则（随机策略、群组问候与默认问候的优先级）。
3. **世界书与角色的绑定模型**：条目是内嵌于角色卡还是独立存储后引用？导入导出时条目随卡携带的边界（导出检查清单显示「12 条已包含」，需确认完整携带）。
4. **声明式面板**的行式配置（`字段名 | 标签 | 默认值`）只是原型暂定格式，正式语法与「保留不运行」的存储位置待定；regex 脚本 / js_slate 宏的原样保留字段键名待定。
5. **声音感官语气提示词**与 TTS 合成的对接方式：是创建音色时传入，还是每次合成时作为参数？
6. **音色 ID 的生命周期**：重新创建是否释放旧音色、解绑后音色是否保留、跨角色复用是否允许。
7. **参考音频临时公网 URL** 的上传通道与有效期具体数值，由后端给出；上传失败时的错误形态未在原型中展示。
8. **导入解析的本地执行**：PNG `tEXt` chunk 的读取与 v2 → v3 的字段迁移由前端还是 sidecar 完成？深度提示（depth prompt）字段的契约。
9. **名称唯一性约束**：冲突仅按名称判断还是按名称 + 来源？副本命名规则（原型未展示副本自动重命名方式）。
10. **头像引用的序列化形式**：v3 JSON 中头像「以引用方式保留」的具体字段与解析方。
11. **归档的语义**：归档角色是否参与搜索、能否恢复、与删除的边界。
12. **角色版本号**（原始数据 `version: 3`）的递增规则与用途待确认。
